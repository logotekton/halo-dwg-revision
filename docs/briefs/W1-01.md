# W1-01 Electron + Vite 워크스페이스 골격

- Owner model: Sonnet
- Size: 1.5 d
- Branch: `task/W1-01`
- Wave: 1  Phase: P0

## Context
저장소는 부트스트랩만 된 상태다(루트 `package.json`, `pnpm-workspace.yaml`, `.nvmrc`, `.npmrc`, `CLAUDE.md`, ADR). 앱 코드는 없다. 이 태스크가 데스크톱 앱과 웹 UI의 뼈대, 린트·테스트 도구를 만든다. 먼저 읽을 것: `CLAUDE.md`, `docs/PLAN.md` §1~§3, `docs/adr/0001-stack.md`, `docs/adr/0004-three-isolation.md`.

## Goal
`pnpm install && pnpm dev`를 실행하면 Electron 창이 열리고 제목이 "대명 CAD"이며, 렌더러는 `apps/web`(Vite + React 19 + TS strict)이다. 린트·타입체크·단위 테스트 도구가 갖춰지고, 하드코딩된 한글 UI 문자열과 허용되지 않은 GPL 임포트가 린트에서 실패한다.

## Inputs
- `CLAUDE.md` 버전 핀(Electron 44.1.x, Vite 7, React 19, TS strict).
- 렌더러 로딩 방식(ADR-0002 §3 참고): 개발 시 `apps/web` Vite dev server URL, 프로덕션은 `dmcad://app/index.html` 커스텀 스킴(`protocol.handle`, `standard`, `secure`, `supportFetchAPI`, `corsEnabled`)으로 `apps/web/dist` 서빙.

## Constraints
- `apps/desktop`: electron-vite로 **main + preload만** 빌드(renderer 비활성). `apps/web`은 독립 Vite 앱. 두 패키지 이름은 `@dmcad/desktop`, `@dmcad/web`.
- Electron 보안: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`. CSP 메타: `default-src 'self' dmcad:; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; connect-src 'self' http://127.0.0.1:* ws://127.0.0.1:*; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; font-src 'self' data:`.
- preload는 `contextBridge.exposeInMainWorld('dmcad', {...})`로 최소 API만(현재는 `app.getVersion()`, `app.platform`). 엔진 연결은 W2-01이 추가한다.
- i18n: `i18next` + `react-i18next`, 기본 언어 `ko`, 리소스 `apps/web/src/i18n/ko.json`(중첩 키). main 프로세스 문자열은 `apps/desktop/src/main/strings.ko.json`.
- ESLint flat config(`eslint.config.js`): `typescript-eslint` strict-type-checked, `react-hooks`, `eslint-plugin-i18next`의 `no-literal-string`을 `apps/web/src/**/*.{ts,tsx}`에 적용(JSX 텍스트와 `title`·`aria-label`·`placeholder` 속성 포함, 테스트 파일 제외). `no-restricted-imports`로 `@mlightcad/libredwg-*` 패턴을 `packages/dwg-io-gpl/**`와 `apps/desktop/src/main/ipc/convert.ts` 외 전역 금지.
- Prettier 기본 + `singleQuote: true`, `semi: false`는 쓰지 않는다(기본값 유지).
- Vitest 워크스페이스(`vitest.workspace.ts`)로 `apps/web`(jsdom) 포함. 각 패키지 `package.json`에 `lint`, `typecheck`, `test` 스크립트.
- 신규 의존성은 MIT/BSD/Apache/MPL만. 보고서에 이름·버전·라이선스 목록.
- 렌더러에는 아직 mlightcad를 넣지 않는다(W3-02). UI는 헤더 + 빈 캔버스 영역 + 상태바(문자열 "엔진: 연결 안 됨"은 ko.json 키)로 충분하다.
- macOS에서만 검증한다. Windows는 CI(W2-09)에서.

## Definition of done
- `pnpm install` 후 `pnpm dev`: Electron 창 열림, 제목 "대명 CAD", 콘솔 오류 0.
- `pnpm build` 후 `pnpm --filter @dmcad/desktop start`: `dmcad://app` 로딩으로 같은 화면.
- 테스트:
  - `apps/web/src/i18n/i18n.test.ts` — ko 리소스 로드, 누락 키 감지.
  - `apps/web/lint-fixtures/bad-literal.tsx`에 한글 리터럴을 두고 `pnpm --filter @dmcad/web lint:fixtures`가 **실패 종료 코드**를 내는지 확인하는 `apps/web/scripts/check-lint-fixtures.mjs`(성공 시 exit 0). `pnpm --filter @dmcad/web test`에 포함.
  - `apps/web/lint-fixtures/bad-gpl-import.ts`(`import '@mlightcad/libredwg-web'`)도 같은 방식으로 실패해야 한다.
- `tools/verify.sh` 녹색(worktree에서 직접 실행). verify.sh가 pnpm 단계를 자동 활성화하도록 `pnpm-lock.yaml`이 커밋돼 있어야 한다.
- 문서: `docs/dev/setup.md`(설치·실행·디버그 방법, 한국어).
- 커밋 `W1-01: ...` on `task/W1-01`.

## Acceptance checks (Fable이 실행)
```bash
pnpm install --frozen-lockfile
pnpm -r lint && pnpm -r typecheck && pnpm -r test     # expected: all pass
pnpm --filter @dmcad/web lint:fixtures; echo "exit=$?" # expected: exit!=0
pnpm build                                            # expected: apps/web/dist + apps/desktop/out
tools/verify.sh                                       # expected: VERIFY: PASS
```
Fable은 `pnpm dev`를 직접 실행해 창과 제목을 확인한다.

## Defaults for ambiguity
- electron-vite가 renderer 없이 동작하지 않으면 → main/preload는 `tsup`(esbuild)로 빌드하고 그 사유를 Decisions에 적는다.
- 커스텀 스킴 등록에서 `protocol.handle` 사용이 어려우면 → `registerFileProtocol` 대신 반드시 `protocol.handle`을 쓰되 문제를 보고. 임시로 `loadFile`을 쓰지 않는다.
- React 상태관리는 아직 넣지 않는다(Zustand는 W3-01).
- 스타일: Tailwind 4 설치는 하되 컴포넌트 라이브러리(shadcn/ui)는 W3-01에서.

## Reference implementation
electron-vite 공식 템플릿(react-ts)의 main/preload 구조를 참고하되, renderer는 `apps/web`으로 분리한다.
