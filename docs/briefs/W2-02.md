# W2-02 cad-core 기초: mlightcad 표면 격리 + 레이어 통계 + NDJ 내보내기

- Owner model: Opus
- Size: 2 d
- Branch: `task/W2-02`
- Wave: 2  Phase: P0
- 선행: W1-04(스파이크 문서), W1-05(스키마), W1-03(픽스처) — 모두 main 병합됨

## Context
스파이크(W1-04)가 mlightcad 1.6.3의 API를 실측했고 CadHost 파사드 설계를 제안했다(`docs/spikes/mlightcad-api.md`, 보고서 "Design notes"). 이 태스크는 `packages/cad-core`를 만들어 **mlightcad 임포트를 한 파일에 격리**하고, 파서 교차검증의 뷰어 측 절반인 `statsByLayer`와 NDJ 내보내기를 구현한다. 뷰(WebGL)는 다루지 않는다 — 전부 `@mlightcad/data-model`만으로 Node(vitest)에서 동작해야 한다. 먼저 읽을 것: `CLAUDE.md`, `docs/contracts/stats-definition.md`(통계 계약), `docs/spikes/mlightcad-api.md` 전체, `docs/spikes/mlightcad-capabilities.md`, `packages/schema/README.md`, `packages/schema/src/{stats,ndj,common}/*.json`, `docs/adr/0002-working-dxf.md`.

## Goal
`@halo-cad/cad-core`가 DXF(ArrayBuffer)를 data-model로 열어 (1) `LayerStatsDocument`(스키마 검증 통과)와 (2) NDJ `Document`(스키마 검증 통과)를 내보낸다. F01~F10 픽스처에서 `count_by_type`, `length_sum`, `hatch_area_sum`, `insert_by_block`, `bbox`가 현재 `fixtures/truth`와 계약 임계 안에서 일치한다. `@halo-cad/dwg-io-gpl`이 GPL 변환기 등록과 워커 자산 복사를 담당한다.

## Constraints
- 패키지 `@halo-cad/cad-core`(MIT 스택만: `@mlightcad/data-model@1.14.3`, `@mlightcad/cad-simple-viewer@1.6.3`은 **타입 전용 임포트**로만, `mitt` 명시), `@halo-cad/dwg-io-gpl`(`@mlightcad/libredwg-converter@3.14.3`, `@mlightcad/libredwg-web@0.7.10`). `three@0.172.0`은 peer 충족용으로 cad-core devDependency. 정확 버전 고정(`^` 금지).
- **`packages/cad-core/src/mlightcad-surface.ts`가 `@mlightcad/*`를 임포트하는 유일한 파일.** 나머지 소스는 이 파일의 export만 쓴다. ESLint `no-restricted-imports`로 강제(로컬 설정).
- 공개 API(`src/index.ts`): `openDxf(bytes: ArrayBuffer, opts?: { encoding?: string }): Promise<CadDocumentHandle>`, `statsByLayer(doc, meta: { file_sha256 }): LayerStatsDocument`, `exportNdj(doc, meta): NdjDocument`, `curveLength(entity)`, `entityRef(entity): EntityRef`, `dispose(doc)`. 반환 타입은 `@halo-cad/schema`의 생성 타입만 사용(mlightcad 타입 노출 금지).
- 통계는 `docs/contracts/stats-definition.md`를 문자 그대로 구현한다. ATTRIB는 `attributeIterator()`로 수집해 `text_count`/`text_hash`에 포함, `count_by_type`에서는 제외. 공간은 `ownerId`→BlockTableRecord 이름으로 판단. 타입 키는 `dxfTypeName`.
- `curveLength`는 두 경로(`subGetIntersectCurves()` 합산, `properties.geometry.length`)를 모두 구현하고 테스트에서 상호 대조(±1e-6 상대).
- NDJ: 스키마 `ndj/document.schema.json`의 20종 엔티티로 매핑, 미지원 타입은 `PROXY`에 `original_type`. INSERT 자식(ATTRIB)의 `provenance.path`에 INSERT 핸들.
- `openDxf`는 입력 버퍼를 복사한 뒤 넘긴다(DWG 경로에서 detach되는 문제 예방, 스파이크 결론).
- `dwg-io-gpl`: `registerLibreDwgConverter({ workerBaseUrl })`(브라우저 전용, `AcDbDatabaseConverterManager.instance.register(AcDbFileType.DWG, new AcDbLibreDwgConverter({...}))`), `scripts/copy-worker-assets.mjs`(libredwg-parser-worker.js + libredwg-web.wasm + mtext-renderer-worker.js를 지정 디렉터리로 복사, wasm은 워커 형제 파일), `README.md`에 GPL 고지와 격리 이유. Node 테스트는 export 존재와 복사 스크립트 동작만.
- `skipLibCheck: true`가 필요하면(스파이크 D.1) ADR-0006 초안에 사유와 상류 이슈 링크를 적고 cad-core tsconfig에만 적용.
- 테스트(vitest, Node 환경): F01~F10 각각 `fixtures/generated/F##.dxf`를 열어 stats 산출 → 스키마 검증 통과 → `fixtures/truth/F##.json`의 `totals.count_by_type`, `totals.length_sum`(±0.1%), `totals.hatch_area_sum`(±0.5%), `totals.insert_by_block`, `totals.bbox`(±1mm)와 일치. **주의:** 현재 truth 파일은 옛 형식(평면, ATTRIB 미포함, 해시 정의 다름)이라 `text_count`/`text_hash`/`buckets`는 비교하지 않는다(W2-03이 재생성, 완전 비교는 W2-04). NDJ는 스키마 검증 + 엔티티 수 = `count_by_type` 합. F03 cp949 변형의 한글 텍스트가 R2018 변형과 동일. F10 호스트에서 XREF 블록 참조가 `insert_by_block`에 나타남.
- 성능: F11(20만 엔티티, `fixtures/gen`에서 `--only F11`로 생성해 사용, 커밋 금지) stats < 15초.

## Defaults for ambiguity
- 문서 열기 API는 스파이크 C.1/C.7의 방식(`AcDbDatabase` 직접 생성 + DXF 변환기)을 우선하고, 뷰어 싱글턴(`AcApDocManager`)은 쓰지 않는다.
- MTEXT 텍스트는 원본 `contents`(제어코드 포함)를 해시에 쓴다(계약).
- 스키마 오류를 발견하면 우회하지 말고 패치 제안 + 테스트를 `skip`으로 두고 사유 기록.
