# W2-06 대용량 / WASM OOM 실측과 기본 변환기 결정

- Owner model: Opus
- Size: 1.5 d
- Branch: `task/W2-06`
- Wave: 2  Phase: P0
- 선행: W1-04(스파이크), W2-05(DWG 픽스처), 가능하면 W2-02(cad-core stats)

## Context
브라우저 WASM(libredwg-web) DWG 파싱은 힙 설정 API가 없어 파일 크기 게이트가 유일한 OOM 대응이다(스파이크 C.12). 정본 DXF 변환기 후보는 acad-ts(1차), mlightcad `dxfOut()`(2차), 네이티브 dwg2dxf(3차)다. 이 태스크가 임계값과 기본 변환기를 **측정으로** 결정한다. 먼저 읽을 것: `CLAUDE.md`, `docs/adr/0002-working-dxf.md`, `docs/spikes/mlightcad-api.md` A·C.7·C.11·C.12, `packages/acad-bridge/README.md`, `spikes/mlightcad/README.md`.

## Goal
`docs/spikes/large-file.md`에 파일별·경로별 측정표(엔티티 수, 크기, 파싱 시간, 피크 RSS, 성공/실패)와 결정 문단(브라우저 미리보기 상한, 라이트/엔진 전용 임계, 기본 변환기)을 쓴다. `tools/bench-open.mjs`로 재현 가능해야 한다.

## Files you own
```
docs/spikes/large-file.md
tools/bench-open.mjs
tools/bench/**                       # 보조 스크립트, 결과 JSON
spikes/mlightcad/**                  # 계측 훅 추가 허용(채택 후 삭제 예정 영역)
```

## Forbidden
`apps/**`, `packages/**`(측정만, 수정 금지), `engine/**`, `fixtures/gen/**`(F11·F12 생성은 실행만).

## Constraints
- 측정 대상: F06(소), F11(20만), F12(100만, `--only F12 --large`로 로컬 생성), `samples/`에 실제 DWG가 있으면 전부(>50MB 우선). DWG는 `acad-bridge dxf2dwg`로 생성.
- 경로: (a) 브라우저 libredwg-web 워커(Playwright headless Chromium, 스파이크 앱 재사용) — 피크 메모리는 `performance.memory`가 고정값이라 **Chromium `--js-flags`가 아닌 프로세스 RSS**(`ps`/`/proc` 또는 Playwright CDP `Performance.getMetrics`·`Memory` 도메인)로 측정; (b) Node utilityProcess 상당: acad-ts `dwg2dxf`(RSS·시간); (c) mlightcad data-model `dxfOut()` Node CJS 경로(RSS·시간, 핸들 보존); (d) 네이티브 dwg2dxf는 미설치 → "미측정, 사용자 Homebrew 설치 시 재측정"으로 표기.
- 24GB(이 Mac)와 16GB 시뮬레이션(Node `--max-old-space-size`, Chromium은 파일 크기 축소 실험으로 대체)을 구분해 기록.
- 각 경로의 산출 DXF를 **엔진 `halo-engine stats`(ezdxf)**로 읽어 `fixtures/truth`와 비교한 결과를 표에 포함(변환 충실도): 카운트, 길이, 면적, **`text_count`·`text_hash`(F03·F06의 한글 텍스트 보존)**, `insert_by_block`(F06·F10_grid의 X-TITLE INSERT 손실 여부). W2-05가 확인한 acad-ts 결함 두 가지(비ASCII 텍스트 모지바케, 블록명=레이어명일 때 INSERT 드롭)가 각 경로에 존재하는지가 기본 변환기 결정의 핵심 근거다. `packages/acad-bridge/README.md` "Known acad-ts gaps" 참조.
- 결정 문단은 ADR-0002 §4의 60MB/200MB/600MB 임계값을 실측치로 대체하고, 기본 변환기를 하나 지정하며 그 근거(충실도·속도·메모리·라이선스)를 표로 남긴다. 결정이 ADR과 다르면 ADR 개정 제안을 Shared-file patch에 적는다.
- `tools/bench-open.mjs`: `node tools/bench-open.mjs --paths acad,dxfout,browser --files ...` → `tools/bench/results-<date>.json` + 마크다운 표 출력.
