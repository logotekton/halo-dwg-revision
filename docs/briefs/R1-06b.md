## Context
R1-08(화면 C)이 실측으로 찾은 결함: 뷰어(mlightcad)는 가시성을 **그려지는 엔티티 단위**로 판단한다. 비교 DXF에서 `__CMP_ADDED`/`__CMP_REMOVED` 레이어로 옮긴 엔티티가 INSERT(블록 참조)나 DIMENSION(익명 `*D` 기하 블록)이면, 실제로 그려지는 것은 블록 정의 안의 도형이고 그것들은 원래 레이어(`A-DOOR`, `0` 등)에 그대로 있다. 그래서 (1) "전/후" 보기 모드에서 `__CMP_*` 레이어를 꺼도 문·창·치수 변경이 숨겨지지 않고, (2) 색도 BYLAYER 강제가 블록 내부에 닿지 않아 빨강·시안이 아니라 원래 색으로 보인다. 문·창 이동/추가는 실무에서 가장 흔한 변경이라 R1 안에서 고친다. 엔진이 단일 진실 소스(CLAUDE.md 4)이므로 **뷰어를 고치지 않고 비교 DXF를 고친다**. 먼저 읽을 것: `CLAUDE.md`, `docs/contracts/compare-dxf.md` §2·§3·§8, `docs/dev/compare-engine.md`(DXF 조립 순서·결정론 조치), `engine/src/halo_engine/compare/compare_dxf.py`, `engine/tests/compare/{test_compare_dxf,test_determinism,test_scenarios}.py`, `fixtures/compare/S02_move_door`(INSERT 이동)·`S03_dim_value`(치수)·`S05_added`(INSERT 신설)·`S11_blockdef_change`.

## Goal
비교 DXF에서 `__CMP_ADDED`·`__CMP_REMOVED`에 놓이는 **INSERT와 DIMENSION**이 참조하는 블록 정의를, 레이어와 색을 비교 레이어로 바꾼 **복제 블록**으로 치환한다.

1. 복제 규칙: 원 블록 `NAME`(전 도면이면 이미 `__B_NAME`)에 대해 `__CMPA_NAME`(ADDED용) / `__CMPR_NAME`(REMOVED용)을 만든다. 복제 블록 안의 모든 엔티티는 `layer = __CMP_ADDED|__CMP_REMOVED`, `color = BYLAYER(256)`, `linetype = BYLAYER`, `lineweight = BYLAYER`. 중첩 INSERT는 재귀적으로 같은 규칙의 복제 블록을 참조한다(순환 가드). ATTRIB(참조에 붙은 속성)도 같은 레이어·색으로.
2. DIMENSION: 익명 기하 블록(`*D…`, 전 도면은 `__B__D…`)도 같은 방식으로 복제해 `dimension.dxf.geometry`가 복제 블록을 가리키게 한다(ezdxf가 `audit()`에서 치수를 지우지 않도록 R1-06이 재연결한 방식을 유지).
3. 원래 레이어에 남는(변경 없는) INSERT·DIMENSION은 그대로 둔다. 마크업 DXF(R1-09 `markup.py`)는 대상이 아니다(레이어를 옮기지 않는다).
4. 복제 블록 이름은 결정론적이고 같은 원 블록을 여러 참조가 공유한다(참조마다 복제하지 않는다). 블록 테이블 순서도 결정론(정렬).
5. `handle_to_cluster`·XDATA·사이드카 형식은 바뀌지 않는다. 복제 블록 안의 엔티티는 히트 테스트 대상이 아니므로 XDATA를 달지 않는다(INSERT 자체에만).
