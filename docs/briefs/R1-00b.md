## Context
사용자는 Windows 10·11 x64 노트북에서 **설치본으로만** 확인한다(개발 체크아웃 없음, 셀프호스티드 러너 없음). GitHub Actions `windows-latest`가 `task/**`·`main` 푸시마다 NSIS 설치본을 아티팩트로 만들어야 한다. 현재 패키징은 macOS arm64 전용(W2-08: `tools/package.sh`, `apps/desktop/electron-builder.yml`, `engine/halo-engine.spec`, `engine/scripts/build-sidecar.sh`). ZWCAD COM 브리지(R1-02)는 comtypes(MIT)를 쓰므로 Windows 사이드카에 comtypes가 들어가야 한다. 먼저 읽을 것: `CLAUDE.md`, `docs/contracts/r1.md` §0·§6.1, `docs/dev/packaging.md`, `docs/dev/ci.md`, `docs/dev/engine-sidecar.md`, `.github/workflows/ci.yml`, `apps/desktop/src/main/engine/spawn.ts`, `apps/desktop/scripts/smoke-packaged.mjs`, `docs/adr/0002-working-dxf.md`(ADR 형식).

## Goal
1. `.github/workflows/windows-installer.yml`: `push`(`main`, `task/**`)·`workflow_dispatch`에서 `windows-latest` 잡 하나가 (a) Node 24 + corepack pnpm, (b) uv + Python 3.12 + `uv sync --frozen`, (c) PyInstaller x64 사이드카(`engine/scripts/build-sidecar.sh`, Git Bash), (d) `pnpm build`, (e) electron-builder NSIS x64, (f) `actions/upload-artifact@v4`로 `halo-dwg-revision-windows-x64`(`*.exe` + `latest.yml`) 업로드(보존 14일)를 수행한다. 동시성 그룹은 ref 단위 취소. 실패 시 `engine/dist`·`dist` 로그를 아티팩트로 남긴다.
2. `apps/desktop/electron-builder.yml`에 `win` 타깃(`nsis`, `x64`, `oneClick: false`, `allowToChangeInstallationDirectory: true`, `perMachine: false`, 한국어 설치 UI, 아이콘)을 더한다. mac 타깃은 그대로.
3. `engine/halo-engine.spec`·`engine/scripts/build-sidecar.sh`를 Windows에서도 돌게 한다: `target_arch`는 darwin에서만, 실행 파일 `halo-engine.exe`, 스모크(READY 줄) 검사의 경로·프로세스 종료를 OS별로. Windows에서는 `comtypes`를 `collect_all`·`hiddenimports`로 포함한다.
4. `engine/pyproject.toml`에 `comtypes==<최신 안정 버전>; sys_platform == 'win32'`를 넣고 `uv lock`으로 `uv.lock`을 갱신한다(크로스 플랫폼 해석이라 mac에서 가능). 버전·라이선스(MIT)를 보고서에 적는다.
5. `apps/desktop/src/main/engine/spawn.ts`: Windows에서 사이드카를 `windowsHide: true`로 띄우고 `.exe` 이름을 찾는지 확인·수정한다(단위 테스트 갱신).
6. `docs/adr/0007-zwcad-com-bridge.md`(승인 2026-09-04): comtypes(MIT) 채택, pywin32 배제 이유(라이선스 허용 목록 밖·설치 후처리), 숨은 인스턴스·시스템 변수·시간 제한·재기동·`comtypes.client.gen_dir` 쓰기 위치(`%LOCALAPPDATA%/halo/comtypes_gen`), PyInstaller 수집, macOS 스텁·계약 테스트 방식(`docs/contracts/r1.md` §6.1 인용). `docs/adr/README.md` 표에 행 추가.
7. `docs/dev/packaging.md`·`docs/dev/ci.md`에 Windows 절 추가: 아티팩트 내려받기 → 설치 → 실행 → 문제 시 로그 위치(`%APPDATA%/Halo CAD/logs`)까지 사용자 확인 절차.

## Constraints
- 액션 핀: `actions/checkout@v7`, `actions/setup-node@v7`, `astral-sh/setup-uv@v10.0.1`, `actions/cache@v6`(기존 ci.yml과 같은 버전), `actions/upload-artifact@v4`.
- corepack으로 pnpm(`pnpm/action-setup` 금지, `docs/contracts/wave-2.md`). Windows 러너는 `core.autocrlf false`를 체크아웃 전에.
- Windows 셸은 `bash`(Git Bash) 기본. PowerShell 전용 단계는 두지 않는다.
- 사이드카는 onedir. `console=True` 유지(main이 `windowsHide`로 숨김). 코드 서명 없음(경고만).
- productName·appId는 바꾸지 않는다(`Halo CAD`, `kr.co.daemyung.halocad`) — 이름 변경은 게이트 질문.
- 런타임 외부 네트워크 없음. 텔레메트리 없음. electron-builder 자동 업데이트(`publish`) 설정 금지.
- 이 저장소에는 아직 GitHub 원격이 없다(`git remote -v`는 `halo-cad-local`뿐). **푸시하지 않는다.** 워크플로 YAML은 `python3 -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))"`로 파싱 검사하고, `actionlint`가 있으면 돌린다(없으면 설치하지 않는다).

## Defaults for ambiguity
- comtypes 버전: PyPI 최신 안정판을 `uv lock`이 고르는 값으로 핀(`==`). 보고서에 적는다.
- Windows 설치본 파일 이름: electron-builder 기본(`Halo CAD Setup 0.0.1.exe`). 아티팩트 이름은 `halo-dwg-revision-windows-x64`.
- CI에서 `build-sidecar.sh`의 READY 스모크가 Windows 러너에서 포트 바인딩 문제로 실패하면 `HALO_SIDECAR_SMOKE=0`로 건너뛸 수 있게 하고 기본은 실행.
- 아이콘 변환이 안 되면 electron-builder 기본 아이콘을 쓰고 Follow-ups에 적는다.
