## Context
P0의 모든 임계값·충실도 판단은 합성 픽스처 기준이었다. 사용자가 실제 실시도서 세트를 제공했다: `samples/2026-09-02-실시도서/`(gitignore, 읽기 전용). 구성: `##실시도서(시공도면 수정)/{00_표지,01_건축(38장),02_기계,03_전기,04_통신,05_소방_기계,06_소방_전기,XR(7),99_CTB}`, `#골조샵/{5장, XR(10)}`. DWG 68장(AC1024 66, AC1027 1, AC1032 1), 최대 20.8MB. 부속: 전 공종 PDF(건축 209MB 등), `#골조샵/*골조 수량산출서.xlsx`, `01_건축/#강판 수량표_251028.xlsx`, CTB 3종, `A-810 천장 평면도.dwg`(CH 판정 관련). 먼저 읽을 것: `CLAUDE.md`, `docs/spikes/large-file.md`, `docs/adr/0002-working-dxf.md`(개정 절), `docs/contracts/stats-definition.md`, `tools/bench-open.mjs`, `tools/bench/compare-stats.mjs`, `packages/acad-bridge/README.md`, `spikes/mlightcad/README.md`, `docs/samples/REQUEST.md`.

## Goal
실제 68장에 대해 (1) 파서별 읽기 결과 대조(acad-ts DWG 읽기, libredwg-web 브라우저 파싱, dxfOut→ezdxf), (2) 한글 텍스트·폰트(STYLE 테이블의 SHX/TTF 이름)·XREF 참조 관계·엔티티 수·티어 분포·시간·RSS, (3) 대표 시트 몇 장의 렌더 PNG를 PDF 페이지와 나란히 비교한 충실도 소견을 만들고, P0 결정(기본 변환기·임계값·화이트리스트)을 재보정한다. **원본 도면 내용(이미지·텍스트 본문)은 저장소에 커밋하지 않는다.** 집계 수치, 파일명, 폰트명, 레이어명 통계만 커밋한다.

## Constraints
- 환경: `pnpm install`, `pnpm --filter @halo-cad/schema build`, `pnpm --filter @halo-cad/acad-bridge build`, `pnpm --filter @halo-cad/cad-core build`, `cd spikes/mlightcad && npm ci`. 엔진 `cd engine && uv sync --frozen`.
- 파서별 읽기: (a) `acad-bridge info/stats` DWG 직접, (b) 브라우저 libredwg-web(스파이크 하네스, `bench-open.mjs --paths browser`), (c) `dxfOut()` 산출 DXF(후처리 66/92는 아직 없음 → 그 영향을 `text_count`·해치 면적 부호로 분리 기록) → `halo-engine stats` + `halo-engine crosscheck`. 세 결과의 `entity_count`·`count_by_type`·`text_count`·`text_hash`를 표에. 파서 간 격차가 있으면 **어느 쪽이 맞는지** PDF/렌더로 판별해 기록(P0의 85 vs 200,005 문제의 답).
- 폰트: `dxfOut` DXF의 STYLE 테이블에서 `font`/`bigfont` 파일명을 전수 집계(도면별·전체). mlightcad 기본 폰트 세트(`cad-data` fonts.json)에 있는지 대조 → 누락 폰트 목록(W3-05 입력).
- XREF: 각 호스트의 XREF 블록(`isXref`, `pathName`) 수집 → `XR/` 파일과의 매칭 표(경로 형태: 절대/상대/파일명만). 엔진 `ingest` XREF 해석 순서로 해석되는지 `halo-engine ingest`(search-path `XR/`)로 확인.
- 코드페이지·한글: AC1024는 UTF-8 세대다. `$DWGCODEPAGE`와 한글 텍스트 샘플 수(개수만) 기록, 모지바케 여부 파서별.
- 티어: 엔티티 수 분포와 크기 밀도(B/엔티티)를 실측해 W2-06의 207/26 B 계수와 25만/80만 티어를 검증·재보정.
- 시간·RSS: 20.8MB 전기도서 등 상위 5장에 대해 경로별 `/usr/bin/time -l`.
- 렌더 충실도: 대표 4장(`01_건축/A-810 천장 평면도`, `A-620 화장실 전개도`, `03_전기/*전기도서 (1)`, `#골조샵/250711-목업골조제작도`)을 스파이크 앱에서 PNG로 렌더(`samples/_reports/render/`), PDF의 해당 페이지를 `pdftoppm`이 없으면 macOS `sips`/`qlmanage` 또는 Playwright PDF 뷰로 PNG화해 나란히 저장. 소견은 텍스트로만 커밋(누락 폰트, 해치, 치수, 선종류, 색).
- `labels.csv`: 파일명·도곽 텍스트에서 시트 유형(평면/입면/단면/천장/전개/상세/일람표/표지 등)과 층을 추정해 초안. 확신도 열 포함. 사용자가 교정한다.
- 골든셋 후보: `#골조샵/*골조 수량산출서.xlsx`와 `#강판 수량표*.xlsx`의 시트명·헤더 행만 기록(수치 내용 커밋 금지). 모듈러 골조(강구조) 수량임을 명시하고 P4 콘크리트 룰과의 관계를 소견에 적는다.
- 명령은 3분 제한(`perl -e 'alarm 180; exec @ARGV'`), 대용량 상위 5장은 5분. 배치 실행은 파일 단위로 결과를 JSON에 누적해 중단 후 재개 가능하게.
- 절대 원본 폴더에 쓰지 않는다. 변환 산출물은 `samples/_reports/work/`.
