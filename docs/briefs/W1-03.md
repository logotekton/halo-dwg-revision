# W1-03 합성 DXF 픽스처 생성기

- Owner model: Sonnet
- Size: 1.5 d
- Branch: `task/W1-03`
- Wave: 1  Phase: P0
- 선행: H0(uv + Python 3.12), W1-02가 병행 중이므로 `engine/`에 의존하지 않는다

## Context
실제 국내 DWG 샘플은 2~3주 후에 들어온다. 그동안 뷰어·파서·교차검증·패키징을 검증할 결정론적 합성 도면 세트가 필요하다. 이 생성기는 P3의 apartment 픽스처(W9-05)로 확장되므로 파라미터화된 구조로 만든다. 먼저 읽을 것: `CLAUDE.md`, `docs/PLAN.md` §7 Wave 1·§9, `docs/adr/0002-working-dxf.md`, `docs/adr/0003-height-fields.md`.

## Goal
`uv run python -m fixtures.gen --out fixtures/generated`가 F01~F12 DXF와 `fixtures/truth/F*.json`을 시드 고정으로 생성한다. 같은 명령을 두 번 실행하면 파일 sha256이 동일하다. 각 truth는 파서 교차검증(ADR-0002 §6) 정의와 같은 통계를 담는다.

## Inputs
- 통계 정의(ADR-0002 §6): 레이어·공간별 `count_by_type`, `length_sum`(LINE/LWPOLYLINE/POLYLINE/ARC/CIRCLE), `hatch_area_sum`(경계 면적), `text_count`, `text_hash`(sha1(NFC(text)) 앞 16자리를 핸들 정렬 순으로 이어 다시 sha1), `insert_by_block`, `bbox`.
- 국내 도면 관행: 단위 mm, 레이어명 예 `S-COL`, `S-BEAM`, `S-WALL`, `S-SLAB`, `A-WALL`, `A-DOOR`, `A-WIND`, `A-TEXT`, `A-DIM`, `X-GRID`, `X-TITLE`; 부재 태그 `C1`, `G1`, `B1`, `W1`, `S1`; 창호 `AW1`, `AD1`; 실명 `거실`, `침실1`, `주방`, `욕실`.

## Forbidden
`engine/**`(병행 태스크), `apps/**`, `packages/**`, 루트 파일.

## Constraints
- 생성기는 `fixtures/gen/`의 독립 uv 프로젝트(`requires-python >=3.12`, 의존 `ezdxf==1.4.4`만). 실행: `cd fixtures/gen && uv sync && uv run python -m fixtures_gen --out ../generated --truth ../truth [--only F06] [--large]`.
- 결정론: 모든 난수는 `random.Random(seed)`; ezdxf 문서의 `$TDCREATE`/`$TDUPDATE`/GUID 헤더를 고정값으로 설정하고, 핸들 부여 순서가 실행 간 동일하도록 엔티티 생성 순서를 고정. 두 번 생성 후 sha256 비교 테스트.
- 픽스처 목록(각각 R2018 UTF-8 `F##.dxf` + R2000 cp949 변형 `F##_r2000_cp949.dxf`, 단 R2000에서 표현 불가한 엔티티는 생략하고 truth에 반영):
  - F01 기본 기하: LINE, LWPOLYLINE(열림·닫힘·벌지), POLYLINE, ARC, CIRCLE, ELLIPSE, SPLINE, POINT, 레이어 5개, 색·선종류 다양.
  - F02 블록: 블록 정의 3개(문 `DOOR_900`, 창 `WIN_1800`, 기둥 `COL_600`), INSERT 30개(회전·축척 포함), ATTRIB 2개씩(`TAG`, `SIZE`), 중첩 블록 1개.
  - F03 한글 텍스트: TEXT 20개(회전·정렬 다양, 스타일 2개: `whgtxt.shx` 빅폰트 참조 스타일, TTF 스타일), MTEXT 10개(`\P` 줄바꿈, 폭 지정, 한글+숫자+기호), 특수문자(`%%d`, `Ø`, `㎡`).
  - F04 해치: SOLID 5개, ANSI31 5개, 사용자 패턴 1개, 구멍 있는 경계 2개, 그라디언트 1개(R2018만).
  - F05 치수·지시선: 선형·정렬·각도·반지름·지름·좌표 치수, LEADER, MLEADER(R2018만), 치수 스타일 2개.
  - F06 구조평면: 그리드 X1~X4·Y1~Y3(간격 8400/7200), 그리드 버블 블록, 기둥 12개(600×600 폴리라인 + SOLID 해치 + `C1`/`C2` 태그 텍스트), 보 중심선(점선 레이어, `G1`/`B1` 태그), 슬래브 태그 `S1 T=150`, 도곽 블록 `X-TITLE`(속성: 도면번호 `S-101`, 도면명 `2층 구조평면도`, 축척 `1/100`). truth에 부재 배치(중심 좌표·치수·태그) 포함.
  - F07 부재일람표: LINE 격자 + TEXT로 그린 표 2개(기둥표: 부호/층/단면 b×h/주근/띠철근; 보표: 부호/위치(단부·중앙)/단면/상부근/하부근/늑근), 병합 셀 2곳, 헤더 행. truth에 셀 격자(행·열 경계 좌표)와 셀 텍스트 매트릭스 포함.
  - F08 층고표+레벨: 표(층/SL/FL/층고/CH) 5개 층(B1~4F) — **CH < 층고 − 슬래브** 관계를 만족하는 값; 단면도 시트에 레벨 라인+라벨(`2FL SL+3,300` 형식) 포함. truth에 4필드 값 포함.
  - F09 실: 이중선 벽(두께 200)으로 실 6개, 문 블록(호 포함) 6개, 창 블록 4개, 실명 텍스트, 의도적 벽 갭(150mm) 2곳과 갭 위치를 truth에.
  - F10 XREF: 호스트 `F10_host.dxf`가 `F10_grid.dxf`(그리드·도곽)를 XREF(상대경로)로 참조. truth에 참조 관계.
  - F11 대용량 20만 엔티티(F06을 층별 타일로 복제·변형), F12 100만(`--large` 옵션에서만 생성, 커밋 금지).
- truth JSON 형식은 `packages/schema`의 `stats/layer-stats.schema.json`(W1-05가 병행 작성 중)과 **필드 이름을 맞춘다**: `count_by_type`, `length_sum`, `hatch_area_sum`, `text_count`, `text_hash`, `insert_by_block`, `bbox`, 문서 총계 `totals`. 스키마 파일이 아직 없으면 위 이름을 그대로 쓰고 Decisions에 기록. 픽스처별 추가 truth(부재·셀·레벨·갭)는 `extra` 키 아래.
- 통계는 생성 시 계산하지 말고 **생성된 DXF를 ezdxf로 다시 읽어** 계산한다(독립 검증). 길이는 곡선을 해석식으로(호 길이, 원주), 스플라인은 ezdxf `flattening(0.01)` 근사.
- 테스트(`fixtures/gen/tests/`): 결정론(2회 sha256 동일), 각 픽스처 재읽기 카운트 = truth, cp949 변형에서 한글 텍스트 왕복, F09 갭 위치 검증.
- 커밋 크기: F01~F10 DXF 합계 < 20MB. F11·F12는 gitignore(이미 설정됨).
- 문서 `fixtures/README.md`: 픽스처 표(내용·크기·엔티티 수), 재생성 방법, truth 형식.

## Defaults for ambiguity
- 폰트 파일은 만들지 않는다. 스타일이 `whgtxt.shx`를 **참조**만 하면 충분하다.
- R2000 cp949 변형에서 ezdxf가 인코딩을 자동 처리하지 못하는 항목은 → `doc.encoding = "cp949"`로 저장하고 확인 테스트를 둔다.
- 도곽 크기는 A1(841×594) 기준, 축척 1/100로 모델공간에 배치.
- 슬래브 두께 150, 바닥 마감 두께 100 가정으로 F08 값 산출(예: 층고 3,300 → CH 2,600 이하).
