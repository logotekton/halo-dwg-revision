## Context
R1의 모든 엔진·화면 태스크가 같은 레코드 형식을 써야 한다. 이 태스크가 JSON 스키마(TS·파이썬 코드젠), SQLite 모델·마이그레이션, `compare.yaml`·`frames.yaml` 기본값과 로더를 만든다. 이름·필드는 `docs/contracts/r1.md` §2~§5에 고정돼 있고, 비교 DXF·사이드카 형식은 `docs/contracts/compare-dxf.md`가 정본이다. 먼저 읽을 것: `CLAUDE.md`, `docs/contracts/r1.md`, `docs/contracts/compare-dxf.md`, `packages/schema/README.md`(변경 절차·작성 규약), `packages/schema/src/common/*.schema.json`, `packages/schema/src/sidecar/markup.schema.json`(작성 예), `packages/schema/scripts/*.sh`, `packages/schema/test/examples.test.ts`, `engine/src/halo_engine/db/{models,repos,migrate}.py`, `engine/src/halo_engine/db/alembic/versions/0002_xref_settings.py`, `engine/src/halo_engine/bundle/layout.py`, `engine/tests/bundle/test_db.py`.

## Goal
1. `packages/schema/src/compare/` 스키마 8종(`sheet-frame`, `sheet-pair`, `change`, `cluster`, `run`, `clusters-sidecar`, `compare-set`, `truth`)과 예제(통과 예 각 1 + 거부 예: provenance 누락 change, 알 수 없는 kind, decision 오타 cluster, `handle_to_cluster` 값이 clusters에 없는 sidecar). `test/examples.test.ts` 표 등록, `src/schemas.ts`·`src/validate.ts`·`src/index.ts`에 검증기 노출(`validateClustersSidecar` 등). TS·파이썬 코드젠 산출물을 같은 커밋에.
2. `engine/src/halo_engine/db/models.py`에 계약 §3의 테이블·컬럼 추가, Alembic `0003_compare_records.py`(down_revision = 0002), `repos.py`에 §3의 함수, `bundle/layout.py`에 `compare_dir`·`log_dir`·`compare_yaml`·`frames_yaml`·`compare_pair_dir(pair_id)`와 `ensure_dirs` 확장.
3. `engine/src/halo_engine/compare/__init__.py`, `compare/config.py`(`CompareConfig`·`FramesConfig` pydantic, `load_compare_config(bundle)`·`load_frames_config(bundle)`·`scale_factor(scale_denominator)`), `compare/defaults/compare.yaml`·`frames.yaml`(계약 §5 그대로, 모든 키에 주석). 로더는 번들에 파일이 없으면 기본값을 복사하고, 있으면 기본값 위에 키 단위로 덮는다. 잘못된 키·타입은 `CompareConfigError`로 파일 이름·경로를 담아 실패.
4. 파이썬 쪽 스키마 검증 헬퍼: `halo_schema.validation.assert_valid("compare_clusters_sidecar", payload, ctx)` 등 8종이 동작하게 `gen-python.sh` 산출물을 갱신한다.

## Constraints
- 스키마 작성 규약(`packages/schema/README.md`): 절대 `$ref` URI(`https://schema.halo-cad.internal/v0/compare/...`), `additionalProperties: false`, `oneOf` 분기는 `const`, `allOf`는 `$defs`로. `schema_version: "0.1"`.
- 코드젠은 결정론적: `pnpm --filter @halo-cad/schema build`를 두 번 돌려도 `git status`가 깨끗해야 한다. `gen-python.sh`는 `uv`(`~/.local/bin`)가 필요하다 — `export PATH="$HOME/.local/bin:$PATH"`.
- DB: SQLite 전용 타입 회피, `JSON` 컬럼, ULID PK, FK. 마이그레이션은 빈 번들과 0002까지 적용된 번들 양쪽에서 `upgrade_to_head`가 통과해야 한다. 다운그레이드 함수도 작성.
- `repos.replace_clusters(..., keep_decisions=True)`: 같은 `pair_id`의 기존 클러스터 중 `signature`가 같은 것의 `decision`·`user_label`·`note`를 새 클러스터에 이어받는다(계약 compare-dxf.md §7).
- `compare/config.py`는 ezdxf를 임포트하지 않는다(가벼워야 함). pyyaml `safe_load`만.
- mypy strict는 기존 override 범위(`model.*`)에 `halo_engine.compare.config`를 더하지 않아도 되지만 `uv run mypy`가 통과해야 한다.
- 결정론: 기본값 복사·로드에 시각·난수 없음.

## Defaults for ambiguity
- 스키마의 `bbox`는 `[x0,y0,x1,y1]` 숫자 4개(`common/primitives`에 이미 있으면 그것을 `$ref`, 없으면 `compare/` 안 `$defs`).
- `Change.delta`는 `type: object`, `additionalProperties: true`(kind별 내용은 R1-06이 채운다), 단 `move: [dx,dy]`·`distance: number`는 선택 필드로 미리 정의.
- `Run.files[]` 항목: `{pair_id, sheet_no, path, format: "dwg"|"dxf", writer: "zwcad-com"|"acad-ts"|"dxf-only"}`.
- `CompareSetSummary`는 계약 §7의 필드 그대로. 모르는 값은 `null` 허용.
- `datamodel-code-generator`가 `allOf`·`unevaluatedProperties`를 못 넘기면 README의 기존 규칙대로 pydantic은 형태만, 규칙은 `assert_valid`로.
- Alembic revision id 문자열은 기존 파일 형식을 따른다(`0003_compare_records`).
