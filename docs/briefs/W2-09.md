## Context
개발은 Mac에서만 이뤄지고 Windows 검증은 GitHub Actions 러너로 한다. 첫 CI는 린트·타입·단위·엔진 테스트를 양 OS에서 돌리는 것이다. 패키징 잡은 W2-08 이후 별도 태스크가 붙인다. 먼저 읽을 것: `CLAUDE.md`, `docs/contracts/wave-2.md`(CI 절), `tools/verify.sh`, `apps/*/package.json`, `engine/pyproject.toml`.

## Goal
`.github/workflows/ci.yml`이 push와 PR에서 `macos-14`와 `windows-latest` 매트릭스로 TS 린트·타입체크·단위 테스트, 엔진 ruff·mypy·pytest를 실행하고, mac에서는 `bash tools/verify.sh`도 실행한다. Windows에서 실패하는 항목은 원인을 분석해 고치거나(소유 범위 내) 이슈로 기록한다.

## Files you own
```
.github/workflows/ci.yml
.github/actionlint.yaml            # 필요 시
docs/dev/ci.md
tools/ci/**                        # 러너용 보조 스크립트
```

## Forbidden
앱·엔진 소스(패치 제안만), `tools/verify.sh`, 루트 설정.

## Constraints
- Node 24 + corepack(`corepack enable && corepack prepare --activate`로 `packageManager` 필드 버전 사용), pnpm 스토어 캐시(`actions/cache` 키 = lockfile 해시).
- Python: `astral-sh/setup-uv@v6`(또는 최신) + `uv python install 3.12`; `cd engine && uv sync --frozen`; `uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run pytest -q`.
- TS: `pnpm install --frozen-lockfile`, `pnpm -r lint`, `pnpm -r typecheck`, `pnpm -r test`. Electron 창을 여는 테스트는 CI에서 실행하지 않는다(단위만).
- `verify` 잡은 mac에서 `bash tools/verify.sh`. Windows에서는 Git Bash로 `bash tools/verify.sh`를 **시도**하고 실패 시 원인(예: grep 옵션·경로 구분자)을 `docs/dev/ci.md`에 기록하고 `continue-on-error: true`로 두되 보고서 Questions에 올린다.
- 동시성: 같은 브랜치의 이전 실행 취소(`concurrency`).
- 워크플로 파일 검증: `actionlint`가 없으면 `pnpm dlx @action-validator/cli`(있으면) 또는 YAML 파싱 확인. 최종 확인은 실제 실행이다.
- 브랜치 `task/W2-09`를 `origin`에 push해 워크플로를 실제로 실행한다(PR은 만들지 않는다). 결과는 `gh`가 없으므로 사용자가 Actions 탭에서 확인하거나 Fable이 확인한다. 보고서에 실행 URL 패턴(`https://github.com/logotekton/halo-cad/actions`)과 커밋 해시를 적는다.
- 비밀은 사용하지 않는다.

## Definition of done
- `ci.yml`이 문법 오류 없이 파싱되고, push된 브랜치에서 워크플로가 트리거된다.
- macOS 잡 녹색 목표. Windows 잡은 녹색 또는 실패 원인 분석 문서화.
- `docs/dev/ci.md`: 잡 구성, 캐시, 로컬 재현 방법, 알려진 Windows 차이.
- 커밋 `W2-09: ...` on `task/W2-09`, 원격 push.

## Defaults for ambiguity
- Windows에서 `uv sync`가 특정 휠 부재로 실패하면 → 해당 패키지와 오류를 문서화하고 잡을 `continue-on-error`로 두되 Questions에 명시(이 정보 자체가 G0 산출물).
- Windows 러너의 pnpm 빌드 스크립트 승인 문제는 `pnpm-workspace.yaml`의 `allowBuilds`가 해결한다(이미 main에 있음).
