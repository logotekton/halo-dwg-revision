# 도면 변경 비교·표기 도구 구축 계획 — 팀장 보고용 (틀 v2)

작성: 2026-09-03 · 독자: 팀장(현장관리 관점) · 형식: HTML 한 페이지(격식 없음, 그림·표 위주) · 대상 사용자: 현장관리자

> 한 문장: 설계사에서 변경 도면이 오면, CAD를 열지 않고도 "어느 도곽의 무엇이 바뀌었는지"를 구름표시와 변경표로 즉시 확인한다.

---

## 1. 지금의 문제 (현장관리자 관점)
- 변경 도면 세트가 오면 어느 시트가 바뀌었는지 사람이 한 장씩 겹쳐 봐야 한다. 수십 개 도곽이 한 파일에 들어 있어 더 어렵다.
- 놓친 변경이 시공 오류·재작업으로 이어진다. [사례 문장 1~2개, 숫자는 없음 → "파일럿에서 측정" 명시]
- 실도면 실태(실시도서 68장): 모델공간 단독, 도곽(표제란 블록)이 시트 단위, XREF 133건 상대경로, 폰트 52종 누락. → 비교 단위는 파일이 아니라 **도곽**이어야 하고, 표제란 텍스트는 OCR 없이 직접 읽힌다.

## 2. 제안: 변경 전·후 도면 비교·표기 도구 (로컬 전용)
2.1 두 가지 사용 방식과 권장
| 방식 | 내용 | 장단점 | 권장 |
|---|---|---|---|
| ② 외부 앱(권장, 1차) | CAD를 열지 않고 변경 전·후 파일을 끌어다 놓으면 도곽 매칭 → 비교 → 구름표시·변경표 생성 | 사용성 최상, CAD 좌석 불필요, 이미 만든 엔진 재사용 | 1차 |
| ① ZWCAD 애드인(2차) | ZWCAD 안에서 "이전 리비전과 비교" 명령 → 같은 엔진 결과를 도면 위에 표시 | 설계 담당·CAD 사용자에게 편함, ZWCAD 버전 종속 | 2차(얇은 껍데기) |
2.2 동작 흐름(그림): 파일 2세트 투입 → 도곽 추출·제목 매칭 → 엔티티 비교 → 변경 영역 묶음 → 구름표시·변경점 번호 → 사용자 검토(채택/제외) → 산출물.
2.3 산출물: (a) 마크업 DWG/DXF(원본 불변, 별도 레이어에 구름표시·번호) (b) 앱 화면 전·후 겹쳐 보기 (c) 변경표(도곽별: 추가/삭제/이동/수정 수, 바뀐 텍스트·치수·날짜, 리비전 기호) HTML/엑셀.
2.4 부가 기능(같은 기술): 도곽 일괄 편집(날짜·리비전 기호·발행처), 도곽 목록·PDF 페이지 대조.
2.5 범위 제외: 서버·클라우드·외부 공유·권한·알림, 설계 편집(ZWCAD가 담당), 물량 비교(적산 단계).

## 3. 현장관리자 시나리오 (하나의 흐름으로)
1. 변경 도면 세트 수신(메일·USB) → 앱에 "변경 전" 폴더와 "변경 후" 폴더 지정.
2. 앱이 도곽을 뽑아 제목·도면번호로 짝을 맞춘다. 짝이 없는 도곽(신규·삭제 시트)은 따로 표시.
3. 도곽별 변경 요약표가 뜬다. 변경 많은 순으로 정렬.
4. 도곽을 클릭하면 전·후를 겹쳐 보여주고 변경 영역에 번호가 붙는다. 사소한 변경(레이어 색, 미세 이동)은 필터로 숨김.
5. 번호별로 "실제 변경/무시" 판단을 남긴다(사용자 검토).
6. 마크업 도면과 변경표를 내보내 현장·협력사에 배포. ZWCAD가 있으면 마크업 도면을 열어 확인.
[채울 것: 화면 스케치 3장]

## 4. 왜 가능한가 (기술 근거, 비전문가용)
- 표제란은 벡터 텍스트·블록 속성 → OCR 불필요. 실도면에서 표제란 수 = PDF 페이지 수 6/6 공종 일치 확인.
- 비교는 엔티티 핸들·기하·텍스트 기준(픽셀 비교 아님) → "어느 선이 바뀌었는지"까지 나온다.
- 이미 검증된 부품: 파일 인입·정본화(DXF), 통계·교차검증(3파서 일치), XREF 해석(115/115), 브라우저 뷰어(한글 렌더 확인), 실도면 68장 실측.
- 원본 불변: 원본은 절대 덮어쓰지 않고 마크업은 파생 파일.
- 무료 스택, 라이선스 준수(GPL 격리, ODA 미사용). ZWCAD는 열람·2차 애드인·검증에 활용.

## 5. 단계와 산출물
| 단계 | 내용 | 확인 방법 |
|---|---|---|
| M1 도곽 추출·매칭 | 파일 속 도곽 목록, 제목·번호 매칭, 신규·삭제 감지 | 실시도서 68장에서 도곽 전수 추출, PDF 페이지 수와 일치 |
| M2 비교·표기 | 도곽별 엔티티 비교, 변경 영역 묶음, 구름표시·번호, 마크업 DWG | 실제 리비전 쌍(변경 전·후)에서 알려진 변경 100% 검출, 오탐 검토 |
| M3 검토 화면·변경표 | 전·후 겹쳐 보기, 채택/제외, 변경표·PDF | 현장관리자 1인 시연 |
| M4 도곽 일괄 편집·ZWCAD 애드인(2차) | 날짜·리비전 일괄 변경, ZWCAD 명령 | ZWCAD에서 결과 열림 |
[채울 것: 기간. 변경 전·후 실제 리비전 쌍 확보가 M2의 전제]

## 6. 리스크
- 변경 전·후 파일의 도곽 제목이 달라 매칭 실패 → 번호·위치·유사도 보조 매칭 + 수동 짝 맞춤.
- 설계사가 도면을 통째로 다시 그려 핸들이 바뀜 → 기하 지문 매칭(이미 설계됨).
- 변경 폭주(레이어·색만 바뀐 경우) → 사소한 변경 필터·가중치.
- 폰트 누락으로 화면 표시 어긋남 → 맑은 고딕 대체, 폰트 추가 기능.
- 대용량 설비 도서 표시 → 도곽 단위 로딩.

## 7. 필요한 것과 결정 요청
- 자원: Windows PC(확보), ZWCAD(확보, 2차용), 소프트웨어 비용 0, 담당자 스티어링 시간.
- **결정 요청:** ① 변경 전·후 실제 리비전 쌍 제공(M2 검증의 전제) ② 산출물 우선순위(마크업 DWG / 앱 화면 / 변경표 PDF) ③ "변경"의 범위 정의(기하·텍스트·치수·레이어 중 무엇을 표기할지) ④ 파일럿 현장·담당자.
