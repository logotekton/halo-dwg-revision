## Goal
1. `compare/diff.py` — `diff_pair(before_doc, after_doc, before_frame, after_frame, config) -> DiffResult(changes, offset, warnings)`
   - 도곽 로컬 좌표: `local = world - frame.bbox.min`. `offset = after.bbox.min - before.bbox.min`(사이드카 `frame.offset_before`).
   - 엔티티 서명(etype별): LINE·LWPOLYLINE·POLYLINE(정점·bulge·닫힘), ARC·CIRCLE·ELLIPSE(중심·반지름·각), SPLINE(제어점·knots), TEXT·MTEXT(서식 코드를 벗긴 문자열·삽입점·높이·회전), DIMENSION(dimtype·defpoints·측정값(`get_measurement`)·재정의 문구), INSERT(블록 이름·삽입점·축척·회전·ATTRIB 태그→값), HATCH(패턴·축척·각·경계 bbox·경계 정점 집합), LEADER·POINT·SOLID·3DFACE(정점), 그 외(etype + bbox). 좌표는 `match.fingerprint_tolerance`(1mm) 격자로 양자화한 값을 지문에, 원값은 비교표에.
   - 두 지문: **위치 포함 지문**(etype, layer, 양자화 기하, 문자열)과 **위치 제외 형상 서명**(기하를 자기 기준점 기준으로 옮긴 것; INSERT는 블록 이름·축척·회전·ATTRIB).
   - 단계: ① 핸들 매칭(같은 핸들·같은 etype) → 속성 비교. ② 남은 것끼리 위치 포함 지문 매칭. 격자 경계 누락을 막기 위해 **이웃 셀(±1)**까지 후보로 모으고 실제 거리 ≤ 1mm인 것 중 가장 가까운 것부터 짝. 같은 지문 여럿이면 거리 순. ③ 남은 것끼리 형상 서명 매칭 → 거리 > 1mm면 `moved`(벡터·거리 기록), 후보 여럿이면 거리 순 유일 배정. ④ 나머지 전에만 → `removed`, 후에만 → `added`.
   - 짝지어진 엔티티의 판정: 기하·문자열 동일 → 변경 없음(레코드 없음). 평행이동만 있고 거리 ≤ `minor.move_tolerance`(0.01) → `minor`, reason `move_le_0_01`. 거리 > 0.01 → `moved`. 문자열만 다름(TEXT/MTEXT/ATTRIB) → `text`. DIMENSION 측정값·재정의 문구 다름 → `dimension`. 그 외 속성 차이 → `modified`. **접기 규칙(구조)**: 레이어·색·선종류·선굵기만 다름 → `minor` reason 각각; HATCH 패턴·축척·경계 bbox·정점 집합 같고 순서·시드만 다름 → `hatch_regen`; DIMENSION 측정값·문구·defpoints 같고 나머지만 다름 → `dim_regen`; MTEXT 서식 벗긴 문자열 같고 원문만 다름 → `mtext_format_only`. 여러 사유는 `+`로. 접힌 항목도 `Change`로 남긴다(`minor=true`).
   - `blockdef`: 전·후 블록 정의를 내부 엔티티 지문 집합으로 비교(같은 이름). 다르면 `blockdef` 변경 1건(`delta.instances = n`, `delta.block = name`), 그 블록의 INSERT는 인스턴스별 `modified`로 내지 않고 `blockdef` 클러스터에 인스턴스 bbox들을 넣는다(bbox 합집합이 커지면 인스턴스별 클러스터로 나눈다 — Defaults 참조).
   - 도곽 밖 엔티티(`entity_handles`에 없는 것)는 비교하지 않는다. `provenance`는 계약대로.
2. `compare/cluster.py` — `build_clusters(changes(minor 제외), frame, config, scale_factor)`: bbox를 `max(frame 긴 변 × grow_ratio, grow_min × scale_factor)`만큼 키워 겹치는 것끼리 union-find. 번호는 읽는 순서(위→아래 행 묶음, 왼쪽→오른쪽). `moved`는 전·후 bbox 합집합. `cluster_signature`(정렬된 `(kind, before_handle, after_handle)` 튜플의 sha256 앞 16자). `cloud_polyline`·`badge_geometry`는 `compare-dxf.md` §5 그대로.
3. `compare/labels.py` — `auto_label(changes) -> str`: `{종류} {행위}[ {수치}]`. 종류는 엔티티 타입 한글(선·폴리라인·원·호·문자·치수·해치·블록 <이름>), 여러 종류면 최다 종류 + `외 n건`. 행위: 신설·삭제·이동 {거리:,.0f}mm {8방위}·치수 {전}→{후}·문구 {전}→{후}·블록 정의 변경 {n}곳·수정.
4. `compare/compare_dxf.py` — `write_compare_dxf(...)`·`write_clusters_json(...)`·`pin_header_for_determinism(doc, run_date)`: `compare-dxf.md` §1~§4·§7·§8 그대로. 후 작업용 DXF를 새 문서에 **엔티티 단위로 복사**(`ezdxf` `copy_to_layout`/`importer`)하되 레이어·블록 테이블을 먼저 옮기고, 전에서 오는 엔티티는 `__B_` 블록 접두·offset 평행이동. XDATA appid `HALO_CMP` 등록. `handle_to_cluster`는 새 문서 핸들. 저장은 `doc.write(stream)` 후 헤더 타임스탬프 줄 정규화 → 바이트.
5. 라우터 `api/routers/compare_clusters.py`(계약 §7): `POST /compare/sets/{id}/run {pair_ids?}` → 202(잡 `compare.run`, `status=comparing → compared`): 짝마다 프로세스 풀에서 두 DXF 로드·diff·cluster·DXF 쓰기 → `replace_changes`·`replace_clusters(keep_decisions=True)`·pair `status`(`changed`/`same`)·카운트·경로. `converter_mismatch`·`unrecognized`·`added`·`removed` 짝은 건너뛴다. `GET /compare/pairs/{pair_id}/clusters` → 사이드카 + DB 판정 병합. `PATCH /compare/pairs/{pair_id}/clusters/{number}` → 판정·문구·메모 저장(사이드카 파일도 갱신해 바이트 동일 규칙과 충돌하지 않게 **decision 필드만** 다시 씀). `GET /compare/pairs/{pair_id}/compare-dxf` → 바이트, ETag.

## Defaults for ambiguity
- `blockdef` 클러스터: 인스턴스 bbox 합집합이 도곽 긴 변의 30%를 넘으면 인스턴스별 클러스터로 나누고 각각 `blockdef`(같은 change 참조).
- 형상 서명이 같은 후보가 거리 동률이면 핸들 정렬 순.
- 회전·미러 이동 판정은 2주차(R2-03). R1은 평행이동만 `moved`, 회전·미러는 `modified`.
- 접힌 항목(minor)은 클러스터에 넣지 않지만 사이드카 `changes[]`에는 남긴다(`cluster_id: null`).
- 도곽 bbox가 전·후 크기 차 1% 초과면 `warnings`에 `frame_size_differs`를 넣고 계속.
- ezdxf가 저장 시 `$TDUPDATE`류를 덮어쓰면 텍스트 정규화로 해결(§8).
