## Context
세 파서(mlightcad, ezdxf, acad-ts)가 `docs/contracts/stats-definition.md`에 따라 같은 `LayerStatsDocument`를 낸다. 이 태스크는 그 문서들을 정렬·비교해 레이어별 녹/황/적 판정과 리포트를 만드는 도구를 엔진에 넣고, CLI와 API 라우터로 노출한다. 임포트 후 뷰어 stats를 엔진에 보내 비교하는 UI 패널은 W3(P1)에서 붙인다. 먼저 읽을 것: `CLAUDE.md`, `docs/contracts/stats-definition.md`, `docs/adr/0002-working-dxf.md`(§6 교차검증), `engine/src/halo_engine/ingest/stats.py`, `packages/cad-core/README.md`, `packages/acad-bridge/README.md`(드롭 리포트), `fixtures/README.md`.

## Goal
`halo-engine crosscheck --ref <stats.json> --other <stats.json> [--whitelist <yaml>] --out <report>`가 두 통계 문서를 비교해 레이어별 상태(GREEN/AMBER/RED)와 원인(누락 타입, 길이 편차 등)을 JSON+마크다운으로 낸다. `tools/crosscheck.sh`가 F01~F10에 대해 mlightcad·acad-ts·ezdxf 세 문서를 모두 만들고 쌍별 비교를 실행한다. 픽스처에서 셋이 전부 GREEN이어야 하고, 의도적으로 손상한 문서는 RED가 나와야 한다.

## Forbidden

## Constraints
- 비교 규칙은 계약 임계 그대로: `count_by_type`·`insert_by_block`·`text_count`·`text_hash` 정확, `length_sum` ±0.1%, `hatch_area_sum` ±0.5%, `bbox` ±1mm. 버킷은 `(space, layer)`로 정렬해 매칭하고 한쪽에만 있는 버킷은 RED.
- 화이트리스트: `{producer_pair, entity_type | field, reason}` 항목. 매칭되는 차이는 RED→AMBER로 낮추고 리포트에 사유를 인용. 사유 없는 항목은 로드 시 오류.
- 리포트 JSON 스키마는 이 태스크가 `engine/src/halo_engine/validate/crosscheck_report.schema.json`에 정의하고(pydantic 모델에서 생성), 마크다운은 레이어별 표 + 총평. 결과는 `drawing_file.parser_crosscheck`에 저장될 형식이므로 pydantic 모델 `CrosscheckReport`를 `halo_engine.model`에 둔다(mypy strict).
- 신뢰도 연동 준비: 리포트에 `red_layers: [..]`를 두어 이후 라우팅이 근거 레이어 감점에 쓸 수 있게 한다.
- API: `POST /api/v1/files/crosscheck` 본문 `{ reference: LayerStatsDocument, other: LayerStatsDocument, whitelist?: string }` → `CrosscheckReport`. 토큰 필수.
- `tools/crosscheck.sh`: (1) `pnpm --filter @halo-cad/cad-core exec node dist/cli.js stats F##.dxf`(cad-core에 CLI가 없으면 짧은 Node 스크립트 `tools/crosscheck/mlightcad-stats.mjs` 작성) (2) `acad-bridge stats` (3) `halo-engine stats` → 세 문서 → 쌍별 crosscheck → `docs/spikes/crosscheck-fixtures.md` 갱신. F01~F10 전부 GREEN이 기준. 격차가 있으면 화이트리스트에 사유와 함께 넣되, **카운트 격차는 화이트리스트 금지**(계약 위반은 해당 태스크에 패치 제안).
- 손상 테스트: F06 stats에서 LINE 2개 제거 → RED with reason `count_by_type.LINE 24→22`.
- 성능: 문서 크기와 무관하게 <1초.

## Definition of done
- `cd engine && uv run pytest -q` 통과(validate 테스트 포함), ruff/mypy 청결.
- `tools/crosscheck.sh` 실행 결과 F01~F10 × 3쌍 전부 GREEN(또는 사유 있는 AMBER), `docs/spikes/crosscheck-fixtures.md` 표 커밋.
- `tools/verify.sh` 녹색. 커밋 `W2-04: ...` on `task/W2-04`.

## Acceptance checks (Fable이 실행)

```bash
cd engine && uv run halo-engine crosscheck --ref /tmp/f06.ezdxf.json --other /tmp/f06.broken.json --out /tmp/rep && grep -c RED /tmp/rep.md   # expected: >=1
```

## Defaults for ambiguity
- 두 문서의 `file_sha256`이 다르면(DWG vs DXF 변환본) 경고만 내고 비교는 진행(플래그 `--allow-sha-mismatch`).
- 마크다운 표는 한국어 헤더.
