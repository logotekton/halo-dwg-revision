# W1-05 스키마 v0 + 코드젠

- Owner model: Opus
- Size: 1.5 d
- Branch: `task/W1-05`
- Wave: 1  Phase: P0

## Context
뷰어(TypeScript)와 엔진(Python)이 주고받는 데이터 형식이 하나여야 한다: 정규화 엔티티(NDJ), 레이어 통계(파서 교차검증), 근거 참조(EntityRef), 레벨 관측, 사이드카(마크업·태깅), 3D 브리지 메시지. `packages/schema`가 JSON Schema를 단일 진실 소스로 두고 TS와 pydantic을 생성한다. 이 패키지는 이후 Fable 소유가 된다. 먼저 읽을 것: `CLAUDE.md`, `docs/PLAN.md` §4·§5, `docs/adr/0002-working-dxf.md`, `docs/adr/0003-height-fields.md`, `docs/adr/0004-three-isolation.md`.

## Goal
`packages/schema`에 JSON Schema(draft 2020-12) v0, 예제 문서, TS 타입·런타임 검증기 생성, Python pydantic v2 생성 스크립트, 양쪽 왕복 테스트를 만든다. 높이 규칙(ADR-0003)이 스키마 수준에서 강제된다.

## Inputs
- `docs/PLAN.md` §4 데이터 모델의 필드 이름을 그대로 쓴다(snake_case).
- `docs/adr/0002-working-dxf.md` §6 통계 정의(레이어·공간별 타입 카운트, 길이 합, 해치 면적 합, 텍스트 해시, 블록명별 INSERT 수, bbox).
- `docs/adr/0004-three-isolation.md` 브리지 메시지 목록.

## Constraints
- 패키지 이름 `@halo-cad/schema`. 스크립트: `build`(코드젠), `test`(vitest), `lint`, `typecheck`.
- 스키마 파일(`packages/schema/src/`):
  - `common/provenance.schema.json` — `{file, handle, path[], space, role?}`; `file`은 ULID 또는 sha256 문자열, `handle`은 대문자 16진 문자열, `space`는 `MODEL` 또는 `PAPER:<layout>`.
  - `common/entity-ref.schema.json` — provenance와 동일 구조에 `role` 선택.
  - `ndj/document.schema.json` — 헤더(`file_sha256`, `dwg_version` AC1014~AC1032, `codepage_declared`, `codepage_effective`, `insunits`, `layers[]`, `blocks[]`, `layouts[]`), `entities[]`.
  - `ndj/entity.schema.json` — `type`으로 분기(`oneOf` + `discriminator` 주석): LINE, LWPOLYLINE, POLYLINE, ARC, CIRCLE, ELLIPSE, SPLINE(control+flattened), TEXT, MTEXT(raw+plain), ATTRIB, ATTDEF, INSERT(변환·자식 provenance path), HATCH(경계 루프·패턴·면적), DIMENSION(유형·측정값·텍스트), LEADER, MLEADER, SOLID, POINT, `3DFACE`, PROXY. 모든 엔티티에 `provenance` **필수**, `layer`, `bbox`.
  - `stats/layer-stats.schema.json` — 파서 교차검증용. 레이어·공간별 `{count_by_type, length_sum, hatch_area_sum, text_count, text_hash, insert_by_block, bbox}` + 문서 총계. `stats.ts`와 `stats.py`가 같은 스키마로 검증한다.
  - `levels/level-observation.schema.json` — `kind` enum **`SL|FL|FLOOR_HEIGHT|CH`**, `value_mm`, `source` enum(`ELEVATION|SECTION|STRUCT_PLAN|LEVEL_TABLE|FINISH_SCHEDULE|USER`), `evidence[]`, `confidence`, `raw_text`.
  - `levels/floor-levels.schema.json` — 층별 확정값 4개와 각 `_source_observation_id`, `_method`(`READ|DERIVED_SL_DIFF|USER`), `conflicts[]`.
  - `levels/consistency-check.schema.json` — 검사 정의 형식 `{id, left_kind, right_kind, operator, tolerance_mm}`. **제약:** `operator`가 `EQ`일 때 `left_kind`·`right_kind`는 같은 기준 집합(`SL`, `FL`, `FLOOR_HEIGHT` 중 `SL`↔`SL`, `FL`↔`FL`, `FLOOR_HEIGHT`↔`FLOOR_HEIGHT`)만 허용하고, `CH`가 한쪽에 오면 `operator`는 `LT|LE|GT|GE`만 허용한다. JSON Schema `if/then/not`으로 표현하고 예제로 증명한다.
  - `sidecar/markup.schema.json`(구름/화살표/메모/자유선, 작성자·시각·상태), `sidecar/tags.schema.json`(엔티티 태깅·분류 override, `stable_key` 포함).
  - `bridge/messages.schema.json` — 3D iframe postMessage: `load`, `select`, `colorize`, `camera`, `ready`, `selected`, `error` (각 payload 정의, `protocol_version`).
- 코드젠:
  - TS: `json-schema-to-typescript` → `gen/ts/*.d.ts`; 런타임 검증은 `ajv`(2020-12) + `ajv-formats`로 `src/validate.ts`에 컴파일된 검증기 export. 생성물은 커밋한다(CI가 재생성 후 diff 없음을 검사).
  - Python: `datamodel-code-generator`(pydantic v2 출력) → `gen/python/halo_schema/`(패키지, `pyproject.toml` 포함, 의존 pydantic≥2.9). 스크립트 `scripts/gen-python.sh`는 `uv run --with datamodel-code-generator ...`를 사용. **이 Mac에 아직 uv/Python 3.12가 없을 수 있다.** 있으면 실행하고 산출물을 커밋, 없으면 스크립트·테스트를 준비하고 보고서에 "Python 코드젠 미실행(uv 없음)"으로 명시.
- 예제(`examples/`): `f06.ndj.json`(구조평면 소형: 기둥 사각 4개, 보 중심선, 태그 텍스트, INSERT 1개, HATCH 1개), `layer-stats.f06.json`, `levels.ok.json`, `levels.bad-ch-eq-sl.json`(거부돼야 함), `consistency.ok.json`, `consistency.bad.json`, `markup.json`, `tags.json`, `bridge.*.json`. 예제의 수치는 mm이며 소형이어도 실제 도면 비율을 흉내낸다.
- 테스트(vitest): 모든 `examples/*.json`이 해당 스키마에 대해 기대대로 통과/거부. 특히 (a) `provenance.handle` 누락 거부, (b) `CH == SL` 검사 정의 거부, (c) `CH < FLOOR_HEIGHT` 검사 정의 허용, (d) 알 수 없는 엔티티 `type` 거부, (e) 통계 문서 왕복.
- Python 테스트(pytest, `gen/python/tests/`): 같은 예제를 pydantic 모델로 로드/거부. uv가 없으면 작성만.
- 문서: `packages/schema/README.md`(스키마 목록, 변경 절차: 스키마 수정 → `pnpm build` → 생성물 커밋 → 양쪽 테스트, 버전 정책 `schema_version` 필드).

## Defaults for ambiguity
- 필드 이름이 PLAN과 ADR에서 다르면 → PLAN §4를 따르고 차이를 Decisions에 기록.
- `discriminator`는 JSON Schema 표준이 아니므로 → `oneOf` + 각 분기에 `type: const`로 표현하고 `x-discriminator` 확장 키를 문서용으로 둔다.
- 기하 좌표 표현은 `[x, y]` 또는 `[x, y, z]` 숫자 배열(mm)로 통일. 곡선은 원본 파라미터 + `flattened`(선분 근사, 선택) 둘 다.
- 텍스트 해시는 `sha1(NFC(text))`의 앞 16자리로 정의하고 스키마 `description`에 명시.
