## 판정 요약 (2026-09-02, Fable)

**결과.** Wave 0~2(15개 태스크)를 main에 병합했다. Electron 셸, 파이썬 엔진 사이드카(READY 핸드셰이크·재시작·프로세스 트리 종료), 스키마(TS·pydantic 코드젠, 높이 규칙 스키마 강제), 합성 픽스처 F01~F12, mlightcad 격리 패키지(cad-core)와 GPL 경계 패키지, ezdxf 인입·정본 DXF·XREF 임베드, acad-ts 브리지와 DWG 픽스처, 3파서 교차검증 도구(33건 RED 0), 대용량 실측, macOS arm64 패키징(dmg), Playwright e2e, GitHub Actions CI(macOS·Windows 녹색).

**확정된 기술 결정(ADR-0002 개정, `docs/contracts/stats-definition.md`).**
1. DWG→DXF 기본 변환기는 mlightcad `dxfOut()`(숨김 BrowserWindow에서 실행), acad-ts는 보조. 근거: acad-ts 산출 DXF는 ezdxf가 읽지 못하고 100만 엔티티에서 스택 오버플로.
2. 변환 성공 판정은 stats 교차검증 통과(차단 게이트). libredwg-web이 오류 없이 20만 중 85개만 반환한 사례.
3. 대용량 티어는 엔티티 수 기준 25만/80만. 파일 크기는 파싱 전 추정에만 사용.
4. 통계 키는 raw DXF 타입명, 곡선 길이의 정본은 ezdxf, 텍스트 레이어 bbox는 AMBER, 감점 계수는 P4 룰 YAML.
5. 픽스처의 ATTRIB 소유자는 INSERT 핸들(AutoCAD 방식).

**P0에서 잡은 결함.** Windows에서 `os.kill(pid, 0)`이 부모 프로세스(Electron)를 종료시키는 버그, Windows 런처 exe와 서버 pid 불일치, acad-ts의 한글 디코딩(우회 완료)·INSERT 드롭·DXF 라이터 결함, mlightcad `dxfOut()`의 INSERT 66·HATCH 92 플래그 누락, Electron 파일 경로 실행 시 앱 경로 오해석.

**P1(W3) 착수 시 반드시 반영할 후속.** (1) W3-02 CadHost: `dxfOut()` 후처리 2건 + 숨김 윈도 변환기 + 뷰어 렌더 포함 A 티어 경계 재확인 + NURBS 자체 평탄화(스플라인 길이). (2) 엔진 `ingest/stats`가 죽은 ATTRIB·영벡터에서 예외 대신 진단을 내도록. (3) acad-bridge DXF 라이터 결함 수복(폴백 유지 시). (4) `packages/schema`에 `CrosscheckReport` TS 타입, `drawing_file.parser_crosscheck` 저장 배선. (5) electron-log 도입, `vitest.workspace.ts`에 schema·acad-bridge 포함.

**미충족·조건부.** 기준 5의 "픽스처 열기"는 뷰어 통합(P1)에서 확인. 실제 국내 DWG 미확보로 모든 임계값·충실도 판단은 합성 픽스처 기준(재보정 필요).
