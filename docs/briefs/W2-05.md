## Context
DWG는 데스크톱 Node 측에서 `@node-projects/acad-ts`(MIT, ACadSharp 포트, R14~2018 읽기·쓰기)로 다룬다(ADR-0002 1차 변환기 후보). 이 태스크는 그 브리지를 만들고, AutoCAD 없이 **DWG 픽스처를 생성**해 G0의 DWG 검증을 가능하게 하며, 세 번째 파서의 레이어 통계를 낸다. 먼저 읽을 것: `CLAUDE.md`, `docs/contracts/stats-definition.md`, `docs/adr/0002-working-dxf.md`, `packages/schema/src/stats/layer-stats.schema.json`, `fixtures/README.md`, https://github.com/node-projects/acad-ts (README, examples).

## Goal
`@halo-cad/acad-bridge` CLI가 `dwg2dxf`, `dxf2dwg`, `stats`를 제공하고, `fixtures/generated/F01..F10.dwg`(AC1027)를 생성해 커밋한다. acad-ts로 읽은 F01~F10의 통계가 계약 임계 안에서 현재 truth의 `count_by_type`/`length_sum`/`hatch_area_sum`/`insert_by_block`와 일치한다.

## Constraints
- 패키지 `@halo-cad/acad-bridge`, 의존 `@node-projects/acad-ts@3.1.0`(정확 고정), Node 24 ESM. CLI 엔트리 `bin/acad-bridge.mjs`(tsup 또는 tsc 빌드), 서브커맨드: `dwg2dxf <in> <out> [--version AC1032]`, `dxf2dwg <in> <out> [--version AC1027]`, `stats <in.dwg|in.dxf> --out <json>`, `info <in>`(버전·코드페이지·엔티티 수).
- `stats`는 `docs/contracts/stats-definition.md`를 그대로 구현하고 `producer: "acad-ts"`, 스키마 검증(`@halo-cad/schema`의 `validateLayerStats` 사용).
- DWG 픽스처: `fixtures/generated/F##.dxf`(R2018)를 `dxf2dwg`로 AC1027 DWG로 저장. F10은 호스트·grid 둘 다. 합계 크기 < 10MB. F11/F12 제외(gitignore).
- 왕복 테스트(vitest): (1) DXF→DWG→DXF 후 acad-ts 통계가 원본 DXF 통계와 정확 일치(핸들 보존 여부도 기록) (2) `dwg2dxf` 출력이 유효한 DXF인지 헤더·섹션 검사 (3) F03 cp949 R2000 DXF → DWG → 텍스트 보존.
- **ezdxf 재읽기 검증은 이 태스크에서 하지 않는다**(Python 미사용). 대신 보고서에 "W2-04에서 ezdxf·mlightcad와 대조 필요" 명시.
- acad-ts가 지원하지 않는 엔티티·객체(예: MULTILEADER, 그라디언트 해치, XDATA, 확장 딕셔너리)는 **드롭 리포트**로 수집해 `stats` JSON 옆에 `*.drops.json`으로 남기고 README에 표로 정리. 이는 ADR-0002의 변환기 선택 근거다.
- 성능: F06 dwg2dxf < 2초, F11 DXF 읽기 시간 기록(생성은 `fixtures/gen`에서 `--only F11`).
