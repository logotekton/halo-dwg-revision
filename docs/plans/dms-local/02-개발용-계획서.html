리비전 도면 관리 앱 개발용 계획서

변경 전·후 DWG 세트를 넣으면 마크업 DWG, 변경 리스트, 리비전 이력 엑셀이 나오는 로컬 앱을 기존 Halo CAD 엔진과 셸 위에 2주 안에 만든다. 첫 주는 끝까지 이어지는 얇은 한 줄(MVP), 둘째 주는 리비전 쌍으로 재면서 채운다.

1범위와 전제

만드는 것은 로컬 앱 하나다. 변경 전·후 DWG 폴더 두 개를 넣으면 도곽 단위로 짝을 맞춰 비교하고, 사용자가 검토·승인한 결과를 마크업 DWG, 변경 리스트, 리비전 이력 엑셀로 낸다. 보고용 계획서(01-보고용-계획서.html)에서 확정한 내용을 그대로 전제로 삼고, 여기서는 어떻게 만드는지만 적는다.

확정 전제내용
입력설계사 DWG 세트 두 벌(전·후)과 XR 폴더. 원본은 읽기 전용이며 어느 단계에서도 쓰지 않는다
변환DWG → 작업용 DXF. 백그라운드 ZWCAD(COM)가 있으면 그것으로, 없으면 자체 변환기로. 두 경로 결과를 교차검증한다
비교 단위파일이 아니라 도곽. 표제란 블록 속성(도면번호·도면명)으로 전·후를 짝짓는다
변경 범위기하·치수 1순위, 텍스트 2순위. 레이어·색·선종류만 바뀐 것은 표기하지 않고 접는다. 레이어·블록 이름은 설명의 힌트
검토화면 C에서 항목마다 승인·무시, 설명 수정, 클라우드 마크 직접 그리기(폴리라인)와 텍스트 추가
출력전체 도곽이 기본, 선택 도곽은 대화상자. 마크업 DWG(REV-CLOUD 레이어) + 도곽별 리비전 표 + 전체 변경 리스트. ZWCAD가 실행 중이면 COM으로 바로 삽입, 아니면 DXF 조각·표 텍스트
이력화면 C → D로 넘어갈 때 프로젝트 폴더의 리비전 이력 엑셀에 실행 날짜 시트를 자동 추가
화면A 세트 지정, B 도곽 목록, C 비교 작업, D 출력. 앱 전체 다크. 캔버스는 안 바뀜 원색·후에만 빨강·전에만 시안
기간2주. 1주 MVP, 2주 테스트·상세 개발. 개발 작업일 기준이고 담당자 검증은 병행

범위 밖

서버·계정·알림, 폴더 관리 체계, 도곽 일괄 편집(설계사 업무), 배포용 PDF, 물량 비교, 자체 CAD 편집 기능. 2차 애드인은 2주 마지막 날 하루만 배정한다.

2아키텍처

새로 세우지 않는다. Halo CAD의 Electron 셸, React UI, 파이썬 엔진, 스키마 패키지를 그대로 쓰고 비교 파이프라인과 화면 네 장을 얹는다. 엔진이 단일 진실 소스이고, 화면은 엔진이 만든 파일과 JSON을 보여주기만 한다.

비교 DXF라는 한 가지 결정

겹쳐 보기를 뷰어에 새로 그리지 않는다. 엔진이 도곽 짝마다 비교 DXF 한 장을 만든다. 전·후 엔티티를 한 파일에 넣되 비교 상태별 레이어에 배치한다.

레이어담기는 것색보기 모드에서
원래 레이어 그대로전·후 모두 있는 엔티티(후 기준). 비교 전용 레이어를 만들지 않는다원래 레이어 색항상 표시
__CMP_ADDED후에만 있는 엔티티, 이동 후 위치빨강(1)겹쳐 보기·후에서 표시
__CMP_REMOVED전에만 있는 엔티티, 이동 전 위치시안(4)겹쳐 보기·전에서 표시
REV-CLOUD클라우드 마크 폴리라인과 번호 배지빨강(1)항상 표시
__CMP_LABEL번호 배지의 히트 영역과 클러스터 id를 담는 XDATA보이지 않음클릭 판정용

겹쳐 보기·전·후 세 모드는 레이어 켜고 끄기로 끝난다. 나란히 보기는 뷰어 두 개에 전용 DXF와 후용 DXF를 넣고 카메라를 묶는다. 마크업 DWG는 같은 생성기에서 __CMP_* 레이어를 뺀 결과다. 사용자 선택 색은 레이어 색을 바꿔 적용한다.

4파이프라인 알고리즘

단계마다 입력·출력·규칙·기본값을 적는다. 기본값은 compare.yaml에 두고 코드에 박지 않는다. 같은 입력이면 같은 출력이 나와야 하므로 난수와 시각은 쓰지 않고, 정렬 기준을 모두 명시한다.

4.1 인입과 변환

파일 sha1을 키로 파생물 폴더를 캐시한다. 같은 해시면 다시 변환하지 않는다.

경로동작규칙
ZWCAD COM 우선Dispatch("ZWCAD.Application")로 숨은 인스턴스 하나를 띄우고 파일마다 열기(읽기 전용) → SaveAs DXF 2013 → 닫기인스턴스 시작 시 FILEDIA=0, CMDDIA=0, PROXYNOTICE=0, FONTALT=malgun.ttf를 건다. 파일당 시간 제한 120초, 초과 시 프로세스 트리를 죽이고 재기동해 다음 파일로 간다. 실패 파일은 자체 변환기로 넘긴다
자체 변환기 대체ADR-0002의 기본 경로: mlightcad dxfOut()(숨은 BrowserWindow) + 후처리(INSERT 66, HATCH 92, LEADER 치수 스타일, STYLE 빅폰트, 핸들 유일성) + acad-ts info로 XREF 경로·TTF 정보 주입기존 ingest/pipeline을 그대로 호출한다. 새 코드 없음
교차검증두 경로가 모두 가능한 PC에서는 세트당 표본 5개 파일을 양쪽으로 변환해 validate/crosscheck 통계(엔티티 수·레이어·블록·텍스트 수)를 비교불일치가 나면 화면 A에 경고를 띄우고 ZWCAD 결과를 쓴다. 불일치 목록은 .halo/log/에 남긴다
XREF기존 ingest/xref: ..\XR\ 상대경로 해석, macOS NFD 정규화, 세트 폴더 옆 XR 폴더 자동 탐색해석 실패는 도곽 목록에 "참조 누락" 태그로 보이고 비교는 계속한다
폰트DXF의 STYLE 테이블에서 SHX·TTF 이름을 모아 시스템 폰트와 대조누락이 있으면 화면 A에서 고지하고 "설치 안내" 또는 "맑은 고딕 대체" 중 하나를 고르게 한다. 선택은 프로젝트 설정에 저장

4.2 도곽 추출

도곽은 표제란 블록으로 찾는다. 실도면 68장에서 표제란 블록 수가 PDF 페이지 수와 일치했으므로 이 규칙이 기준이다.

  1. 모델공간의 INSERT 중 ATTRIB를 3개 이상 가진 블록을 후보로 모은다. 태그 이름이 DWG_NO|DWGNO|SHEET|도면번호|NO 중 하나와 TITLE|DWG_NAME|도면명|제목 중 하나에 맞으면 표제란으로 확정한다. 맞는 태그가 없으면 같은 블록 이름이 가장 많이 반복되는 후보를 표제란으로 본다.
  2. 도곽 경계는 표제란 블록을 포함하는 가장 작은 닫힌 사각형 폴리라인이다. 없으면 표제란 블록 bbox를 기준으로 표제란이 오른쪽 아래에 오도록 세트 안에서 관측된 도곽 크기(최빈값)를 적용한다.
  3. 엔티티는 bbox 중심점이 들어가는 도곽에 배정한다. 어느 도곽에도 안 들어가면 "도곽 밖" 묶음으로 두고 비교에서 뺀다. XREF 참조 엔티티는 삽입점이 속한 도곽에 배정한다.
  4. 도면번호·도면명·축척·날짜는 ATTRIB 문자열이다. 정규화 키는 공백 제거, 전각 → 반각, 대문자, 하이픈 통일로 만든다.

태그 이름 규칙은 frames.yaml에 두고 설계사마다 늘린다. 표제란 블록이 XREF 안에 있는 세트(표지·XR 참조 17장)는 참조를 풀어 같은 규칙을 적용한다.

4.3 도곽 매칭

순서규칙결과
1정규화한 도면번호가 같다짝(번호), 점수 1.0
2번호가 없거나 겹치면 도면명 토큰 자카드 유사도 0.6 이상이고 유일하다짝(제목), 점수 = 유사도
3같은 파일 이름 안에서 도곽 순서(왼쪽 위부터)가 같고 크기가 같다짝(위치), 점수 0.5
4남은 것전에만 있으면 삭제, 후에만 있으면 신규, 둘 다 후보가 여럿이면 짝 없음

짝 없음은 화면 B에서 수동으로 맞추고 SheetPair.match_method=manual로 저장한다. 수동 짝은 같은 프로젝트에서 다음 세트에도 힌트로 쓴다.

4.4 엔티티 비교

도곽 짝마다 전·후 엔티티를 도곽 로컬 좌표로 옮긴 뒤 세 단계로 짝짓는다. 허용오차 τ는 기본 1mm(도면 단위 기준으로 환산)다.

  1. 핸들 매칭. 같은 핸들·같은 타입이면 짝으로 보고 속성을 비교한다. 설계사가 도면을 통째로 다시 그려 핸들이 바뀐 세트에서는 이 단계가 비고 다음 단계로 간다.
  2. 지문 매칭. 남은 엔티티끼리 지문(타입, 레이어, τ로 반올림한 기하 서명, 문자열)이 같으면 짝이다. 같은 지문이 여럿이면 거리 순으로 짝짓는다.
  3. 이동 판정. 위치를 뺀 지문(형상·크기·회전)이 같고 거리가 τ보다 크면 이동이다. 이동 벡터와 거리를 기록하고 전 위치는 removed, 후 위치는 added로 그린다.
  4. 나머지. 전에만 있으면 삭제, 후에만 있으면 추가.
엔티티비교하는 값사소한 변경으로 접는 것(기본값)
LINE·LWPOLYLINE·ARC·CIRCLE·SPLINE정점·반지름·각도(τ 반올림), 닫힘 여부정점 이동이 전부 τ 이하, 레이어·색·선종류·선굵기만 변경
TEXT·MTEXT서식 코드를 벗긴 문자열, 삽입점, 높이, 회전서식 코드만 변경, 삽입점 이동 τ 이하
DIMENSION측정값, 재정의 문구, 치수선 위치값·문구 같고 재생성만 된 것
INSERT블록 이름, 삽입점, 축척, 회전, ATTRIB 문자열삽입점 이동 τ 이하
HATCH패턴 이름, 축척, 경계 bbox경계 bbox 같고 재생성만 된 것
블록 정의블록 테이블 항목별로 내부 엔티티 지문 집합없음. 정의가 바뀌면 인스턴스 수와 함께 한 건으로 낸다

접힌 항목은 버리지 않는다. Change.minor=true로 남겨 화면 C의 접힌 목록에 보이고, 사용자가 펼쳐 승인하면 일반 항목이 된다.

4.5 묶음과 번호

변경(사소한 것 제외)의 bbox를 도곽 긴 변의 2% 또는 300mm 중 큰 값만큼 키운 뒤 겹치는 것끼리 합친다(union-find). 묶음은 왼쪽 위에서 오른쪽, 그다음 아래 순(읽는 순서)으로 번호를 붙인다. 이동은 전·후 위치가 한 묶음에 들어가도록 두 bbox의 합집합으로 계산한다.

클라우드 마크는 묶음 bbox에 여백 150mm를 더한 사각형을 현 길이 300mm의 호로 두른 LWPOLYLINE(bulge 사용)이다. 번호 배지는 오른쪽 위 모서리의 CIRCLE(반지름 200mm)과 가운데 정렬 TEXT다. 크기 값은 도곽 축척에 따라 실제 인쇄 크기가 같아지도록 축척 배율을 곱한다.

4.6 설명 생성

문구는 {종류} {행위}[ {수치}][ · {힌트}] 틀로 만든다. 종류는 사전, 행위와 수치는 변경 종류, 힌트는 위치 규칙에서 온다. 자연어 생성기나 LLM은 실행 중에 쓰지 않는다.

단계규칙없을 때
종류(사전)블록 이름 → 레이어 이름 순으로 사전 정규식을 맞춘다. 프로젝트 → 내장 → 개인 순으로 먼저 맞는 항목을 쓴다2주차: 크기·채움·축선 위치·반복 점수로 추정하고 "(추정)"을 붙인다. 그것도 안 되면 엔티티 타입 이름("폴리라인 5개")
행위added → 신설, removed → 삭제, moved → 이동 {거리}mm {방향}, dimension → 치수 {전} → {후}, text → 문구 {전} → {후}, blockdef → 블록 정의 변경 {n}곳해당 없음
수치이동 거리·방향(동서남북 8방위), 치수·문자 전후 값, 크기(사각형이면 가로×세로)생략
힌트(2주차)묶음 중심에서 3,000mm 안의 가장 가까운 실명 TEXT, 그리드 기호(원 + 한두 글자) 두 개로 만든 "C3 부근"생략

사용자가 화면 C에서 종류를 고치면 그 항목의 레이어·블록 이름 패턴이 프로젝트 사전 끝에 추가된다. 사전은 덧붙이기만 하고 지우지 않는다. 내장 사전 초안은 실도면 세트의 레이어·블록 이름 목록에서 개발 중에 만든다.

4.7 래스터 보조 비교 2주차

객체 비교가 놓친 것을 잡는 안전망이다. ezdxf의 drawing 애드온으로 전·후 도곽을 같은 범위·같은 해상도(긴 변 4,000px)로 그린 뒤 1px 팽창하고 XOR한다. 남은 연결 성분 중 어느 묶음 bbox에도 안 들어가는 것을 "래스터 잔여" 항목으로 만들어 목록 끝에 붙인다. 픽셀 그림은 저장하지 않고 bbox만 남긴다.

4.8 마크업 DWG와 리비전 표

  1. 후 작업용 DXF를 복사한다. 원본 DWG는 건드리지 않는다.
  2. 승인된 묶음의 클라우드 마크와 번호를 REV-CLOUD 레이어에 넣는다. 수동 마크도 같은 레이어다.
  3. 도곽별 리비전 표를 표제란 왼쪽에 LINE과 TEXT로 그린다. TABLE 엔티티는 프록시가 될 수 있어 쓰지 않는다. 열은 번호·내용·일자·담당, 행 높이와 글자 크기는 축척 배율을 곱한다.
  4. 전체 변경 리스트는 첫 도곽에 같은 방식으로 그린다(위치는 8절 결정 뒤 변경).
  5. DWG 저장은 백그라운드 ZWCAD의 SaveAs(2013 형식)가 우선이고, 없으면 acad-ts dxf2dwg다. acad-ts 경로는 ATTRIB 복제 결함(W3-06)이 남아 있어 표제란 블록을 건드리지 않는 조건에서만 쓴다.

4.9 리비전 이력 엑셀

openpyxl로 <프로젝트>/리비전 이력.xlsx를 열거나 만든다. 화면 C에서 D로 넘어가는 순간 실행 id로 한 번만 만든다(같은 실행에서 다시 넘어가면 시트를 덮어쓴다). 시트 이름은 YYYY-MM-DD이고 같은 날 두 번째부터 (2)를 붙인다. 시트 안에는 두 표를 위아래로 둔다.

5화면, API, IPC

화면은 보고용 계획서의 A~D 목업을 그대로 따른다. 여기서는 화면이 부르는 엔진 API와 IPC만 적는다. 모든 긴 작업은 기존 잡 체계(api/jobs, 진행률은 api/ws)를 탄다.

화면엔진 API(/compare 라우터)IPC(main ↔ renderer)
A 세트 지정POST /compare/sets {before_dir, after_dir, options} → job. 진행: 변환 n/N, 도곽 추출, 매칭. GET /compare/sets/{id} 요약(파일·도곽·XR·폰트 누락)dialog:pickFolder, zwcad:status(설치·실행 여부), fonts:install-guide
B 도곽 목록GET /compare/sets/{id}/pairs(상태·변경 수·정렬), POST /compare/pairs/{id}/manual {before_frame, after_frame}, POST /compare/sets/{id}/run 비교 실행 → job없음
C 비교 작업GET /compare/pairs/{id}/clusters, PATCH /compare/clusters/{id} {decision, user_label, kind, note}, POST /compare/pairs/{id}/clusters 수동 마크 {polyline, text}, DELETE /compare/clusters/{id}(수동만), GET /compare/pairs/{id}/compare-dxf(뷰어 로드)없음

뷰어 연결

  • CadHost에 비교 DXF를 열고 레이어 가시성으로 겹쳐 보기·전·후를 바꾼다. 나란히는 CadHost 두 개와 카메라 동기화(뷰 행렬 이벤트 중계)다.
  • 번호 배지 클릭은 뷰어 히트 테스트로 엔티티 핸들을 얻고, 비교 DXF 옆 사이드카 JSON(handle → cluster_id)으로 묶음을 찾는다. 리스트에서 번호를 누르면 묶음 bbox로 카메라를 맞춘다.
  • 수동 마크 그리기는 뷰어 위 폴리라인 입력 모드다. 클릭 점을 도면 좌표로 바꿔 엔진에 보내고, 엔진이 클라우드 폴리라인을 만들어 비교 DXF를 갱신하면 뷰어가 다시 연다.
  • 설정(색·보기 모드·사소한 변경 기준)은 state/viewer와 프로젝트 compare.yaml에 저장한다.

UI 문자열은 apps/web/src/i18n/ko.json 키로만 쓴다(ESLint no-literal-string). 다크 테마 토큰은 보고용 계획서 목업 팔레트를 그대로 옮긴다.

프로젝트는 폴더 하나다. 원본 세트 폴더는 읽기 전용이고, 앱이 쓰는 것은 .halo, 출력 폴더, 이력 엑셀뿐이다. 원본 경로 쓰기는 기존 bundle/guard가 거부한다.

9리스크와 대응

리스크대응
숨은 ZWCAD 인스턴스가 대화상자에서 멈춤시스템 변수로 대화상자 억제, 파일별 시간 제한, 프로세스 트리 종료 후 재기동, 실패 파일은 자체 변환기로. 실패율을 로그에 남긴다
ZWCAD 버전에 따라 DXF 출력이 달라 결정론이 깨짐변환 메타에 ZWCAD 버전을 기록하고, 비교는 변환 결과가 아니라 파생 DXF를 입력으로 하므로 같은 DXF면 결과가 같다. 버전 변경 시 재변환을 권한다
설계사가 통째로 다시 그려 핸들이 전부 바뀜지문 매칭과 이동 판정이 기본 경로다. 합성 쌍에 통째 사본 시나리오를 넣어 오탐 0을 확인한다
해치·치수 재생성 잡음사소한 변경 규칙으로 접는다. 접힌 항목도 목록에 남아 사용자가 펼칠 수 있다
표제란 블록이 XREF 안에 있거나 태그 이름이 다름frames.yaml로 태그 규칙을 늘리고 XREF를 풀어 적용한다. 그래도 못 찾으면 화면 B에 "도곽 미인식" 파일로 보이고 수동 지정 경로를 남긴다
뷰어가 큰 도곽에서 멈춤(헤드리스 8/68)비교 DXF는 도곽 하나 분량이라 부하가 작다. W3-02 뷰어 통합 WIP를 먼저 마무리한다
acad-ts 라이터의 ATTRIB 복제 결함DWG 저장은 ZWCAD 우선. acad-ts는 표제란을 건드리지 않는 조건에서만 대체로 쓴다
macOS 개발과 Windows 실행의 괴리COM 코드는 얇은 브리지로 격리하고 계약 테스트를 스텁으로 돌린다. Windows 확인 작업을 일정에 명시했다
2주 안에 담당자 리비전 쌍이 없음합성 쌍으로 개발을 진행하고 실도면 세트로 인입·도곽을 검증한다. 담당자 쌍은 2주차 측정에만 필요하다

10결정 요청

보고용 계획서의 다섯 가지에 개발 착수에 필요한 세 가지를 더했다. 결정 전까지는 1절의 기본값으로 진행한다.

  1. 착수 시점. 1주차 D1을 어느 날로 잡을지.
  2. 클라우드 마크 규격. 레이어 이름·색·호 크기·번호 표기가 회사 표준과 다르면 그 값.
  3. 리비전 표 양식. 열 구성과 표제란 옆 위치, 전체 변경 리스트를 넣을 도곽(표지 또는 첫 도곽).
  4. 사소한 변경 기준. 이동 허용오차와 접을 항목 종류. 기본값은 1mm와 1절 표.
  5. 도곽 목록 그룹 기준. 공종까지만 묶을지 도면 종류까지 나눌지. 실제 수령 도면을 본 뒤 2주 안에.
  6. ZWCAD 설치 정보. 담당자 PC의 ZWCAD 버전과 에디션, COM 자동화가 되는 라이선스인지. D1 전에 필요하다.
  7. 리비전 쌍 제공 시점. 담당자가 만드는 전·후 쌍을 언제 줄지. 2주차 D6 측정에 쓴다.
  8. Windows 확인 방식. 담당자 PC에서 수동 확인할지, 셀프호스티드 러너를 둘지.
