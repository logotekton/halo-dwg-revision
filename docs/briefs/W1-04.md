# W1-04 mlightcad 통합 스파이크 + 편집 capability 감사

- Owner model: Opus
- Size: 2 d
- Branch: `task/W1-04`
- Wave: 1  Phase: P0

## Context
2D 도면 코어로 `@mlightcad/cad-simple-viewer@1.6.3`(MIT)와 `@mlightcad/libredwg-converter@3.14.3`(GPL, DWG)를 채택했다(ADR-0001). 그러나 실제 API 표면, 워커 배선, 한글 SHX 렌더, `dxfOut()`의 존재와 품질, 편집 명령의 실제 제공 여부는 문서만으로 확인되지 않았다. 이 스파이크가 그 사실을 확정한다. 이후 W3-02(CadHost 파사드), W3-05(폰트), W3-06(XREF), W4-03(편집 명령 보충)이 이 문서를 입력으로 삼는다. 먼저 읽을 것: `CLAUDE.md`, `docs/PLAN.md` §1·§5·§7, `docs/adr/0002-working-dxf.md`.

## Goal
`spikes/mlightcad/`에 독립 Vite 앱을 만들어 DXF와 DWG를 열고, 한글 MTEXT를 렌더하고, 엔티티 열거·히트테스트·선택 이벤트·오버레이·트랜잭션 편집·DXF 내보내기를 실제 코드로 시험한 뒤, 세 문서를 남긴다: API 참조, 편집 capability 매트릭스, 라이선스 트리.

## Inputs
- npm: `@mlightcad/cad-simple-viewer@1.6.3`, `@mlightcad/data-model@1.14.3`, `@mlightcad/three-renderer@1.6.3`, `@mlightcad/mtext-renderer@0.12.x`, `@mlightcad/libredwg-converter@3.14.3`, `@mlightcad/libredwg-web@0.7.10`, `three@0.172.0`.
- 문서: https://github.com/mlightcad/cad-viewer (README, wiki: Architecture, Configure Worker URLs, Self-Hosted Fonts, Entity Modification Best Practices, Plugin System), https://github.com/mlightcad/realdwg-web, API 문서 https://mlightcad.com/cad-viewer/docs/, https://mlightcad.com/realdwg-web/.
- 시험 도면: `spikes/mlightcad/fixtures/`에 **직접 손으로 작성한** 최소 DXF(AC1032 UTF-8: LINE, LWPOLYLINE, CIRCLE, ARC, TEXT(한글), MTEXT(한글, `\P` 줄바꿈), INSERT+ATTRIB(블록 정의 포함), HATCH(SOLID), DIMENSION(선형) 각 1개 이상, 레이어 3개)와 R2000 cp949 변형 1개. DWG는 mlightcad 저장소의 공개 샘플(예: `canteen.dwg`)을 URL과 sha256을 기록하고 사용. 합성 픽스처 세트(W1-03)는 병행 중이라 아직 없다.

## Constraints
- 스파이크는 일회성이다. 코드 품질보다 **사실 확인**이 목적. 단 문서는 이후 태스크의 입력이므로 정확한 식별자(클래스·메서드·이벤트명·옵션 키)를 그대로 적는다.
- 워커 URL 배선(`AcApDocManager.createInstance({ webworkerFileUrls })` 또는 현재 API), DWG 등록(`AcDbDatabaseConverterManager.instance.register(AcDbFileType.DWG, new AcDbLibreDwgConverter({...}))`)을 Vite에서 동작시키고, **Electron(`dmcad://` 커스텀 스킴, electron-vite)에서 동일 배선이 필요한 조건**을 문서에 예측·기록한다.
- 폰트: 기본 CDN `fonts.json`이 아니라 **자체 호스팅**(`baseUrl` 변경)으로 시험한다. 한글 SHX 빅폰트(`whgtxt.shx` 등)와 TTF 대체 경로를 확인한다. `fonts-not-found` 이벤트를 잡아 기록한다.
- 반드시 확인할 사실(각각 "확인됨/불가/조건부"와 코드 위치):
  1. 모델공간 엔티티 열거 API와 필드(타입, 레이어, 핸들, 기하, 텍스트 내용, 블록명·속성값, INSERT 변환).
  2. 레이어별 통계(카운트·길이·면적) 계산에 필요한 기하 접근(`AcDbPolyline` 길이, `AcDbHatch` 면적 등).
  3. 히트테스트/박스 선택/하이라이트/줌(`pick`, `search`, `selectByBox`, `highlight`, `zoomTo`).
  4. 선택 변경·문서 열림·렌더 완료 이벤트.
  5. transient 오버레이(`addTransientEntity`) 및 마크업 API와 사이드카 JSON 형식.
  6. 편집 트랜잭션(`acapRunDatabaseEdit`, undo mark) 사용법과 undo/redo.
  7. **`AcDbDatabase.dxfOut()`** 존재 여부, 출력 DXF 버전, 원본 대비 엔티티·핸들 보존(같은 파일을 다시 열어 카운트 비교). 이는 ADR-0002의 2차 변환 경로 판단에 쓰인다.
  8. 레이아웃(페이퍼 공간) 전환과 뷰포트 드릴다운.
  9. XREF: 자동 해석 유무, 수동 attach 워크플로우 API.
  10. MDI(다중 문서) API.
  11. Node 헤드리스 실행 가능성(`cad-simple-viewer-cli` 또는 Playwright 기반)과 통계 산출 가능성.
  12. WASM 메모리 설정과 DWG 로딩 시간(샘플 DWG 기준).
- 편집 capability 매트릭스: `docs/PLAN.md` §7의 편집 목록(선택/측정/이동/복사/회전/축척/대칭/늘리기/자르기/연장/결합/끊기/분해/간격띄우기/그립/정점 편집/undo/선·폴리라인·사각·원·호·해치·문자·치수·지시선 생성/레이어 CRUD/특성 일치/블록 삽입·속성 편집)을 행으로, 열은 "1.6.3 제공 여부 / 명령명 또는 API / 품질 메모 / 우리가 만들 것인지". "unknown" 행이 없어야 한다.
- 라이선스 트리: `npm ls --all` 또는 `pnpm licenses list`로 `data-model`·`cad-simple-viewer` 의존 트리에 GPL 패키지가 **없음**을 확인하고 기록. `libredwg-*`만 GPL이어야 한다.
- 스크린샷: 한글 MTEXT 픽스처와 샘플 DWG 렌더 결과를 `docs/spikes/img/`에 PNG로 저장(Playwright 또는 수동).

## Defaults for ambiguity
- 특정 API가 문서와 다르면 → 실제 타입 선언(`node_modules/@mlightcad/*/dist/*.d.ts`)을 진실로 삼고 문서 URL과 차이를 기록.
- 샘플 DWG 다운로드가 불가하면 → DXF만으로 진행하고 DWG 항목을 "미검증"으로 명시(단, 이는 G0 항목이므로 보고서 Questions에 올린다).
- 한글 SHX 폰트가 기본 폰트 세트에 없으면 → TTF(Noto Sans KR) 대체 경로로 렌더하고 사실을 기록.
- Electron 통합은 실제로 하지 않아도 되지만, 커스텀 스킴에서 워커·WASM 로딩에 필요한 조건(CSP, MIME, 경로)을 예측해 적는다.
